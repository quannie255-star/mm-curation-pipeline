> **立题** 2026-09-30。用户指令原话：「继续完成开发，使得项目可以更加产品化，部分卡壳的部分
> 可以直接调用 api 连接大厂成熟技术方案，目前的想法是先和 glm 共同协作做出产品，注意产品思维，
> 产品思维，技术独创性不是那么重要，优先产品化，收尾，目标能放在简历上」。
>
> **用户已拍板的三件事（2026-09-30）**：
> 1. **卡壳 → 大厂 API 的覆盖面 = 四类全做**：判官 / 网页抽取 / 语义去重嵌入 / 工业轨时序异常检测。
> 2. **发布形态 = 自包含静态页 + 公网链接**（零后端；Streamlit 门户不对外发布）。
> 3. **收尾线 = 都不砍**：R2/R3 原计划保留，与产品化增量并行；**本轮只调整排序，不删任务**。
>
> 3 条约束继承自 `COLLAB_PLAN.md` §六（协议签名不动 / 基线只增不减 / 非平凡任务先过设计门）。

## 零、一句话产品定义（本文件的第一性约束）

> **给「要拿自己的数据去微调模型」的人一个单机可跑的工具：一条命令出判决书
> （每条样本逐条可归因）、一份证据链（每个对外数字可复算）、一个可点开的页面
> （不用装环境就能看）。**

面试官会问的三句，以及现在能不能答：

| 命题 | 现在的答案 | 还缺什么 |
|---|---|---|
| 清洗真的有用？ | 脏索引 → 净索引 **R@1 0.459 → 0.556（+21%）**，且有训练级证据（CLIP 0.688 vs 0.636） | 无 |
| 在**我的**数据上能用？ | 判据适用性 + 四类真实形态已补；真实轨召回**如实标为"标签口径下的召回"**、误杀标为**上界** | **P1-7 人审队列**（终裁必须靠人） |
| 我凭什么信你的数？ | `claims.json` 66 门面 + `PROOF_CHAIN` 十问索引 | **N-3 覆盖面**（没注册的数字会静默腐烂）+ N-4（最有力的报告页不入库） |

**注意第三行**：这是本项目最贵的一栏，而三审恰恰发现它有个洞（门禁是白名单）。
产品化的第一步不是加功能，是**先把这个洞补上**——否则新做的产品页会重复同一个错误。

## 一、产品思维：S1 先做"看得见"的三件

**产品化 ≠ 加功能。** 本项目功能已经过剩：7 个版本、60 个脚本、690 条测试、
双 CI、10 页签门户、四类模态。**缺的不是能力，是"让人看见"的形态。**
所以本轮的取舍规则只有一条：

> **凡是"外人看不见"的工作，一律排在"外人看得见"的工作之后。**

依据（三审实点）：`README` 里 `V4`/`V5`/`V6`/`V7` 出现 **0 次**（叙事停在 V3）；
`docs/real_data.html`（最有说服力的真实数据页）**被 gitignore**、外人在 GitHub 上点不开；
README 里**没有任何在线链接**。

S1 三件（按顺序，前一件是后一件的素材）：

| # | 产出 | 为什么排这么前 | owner |
|---|---|---|---|
| S1-1 | **产品页**（自包含静态单页，可发布公网） | 简历上能直接放 URL；面试官第一眼看到的是结论不是代码 | 我 |
| S1-2 | **README 产品首页化**（V1→V7 一行演进 + Demo 链接 + 三步可验） | README 是唯一"所有人都会看"的门面（N-5） | 我 |
| S1-3 | **产品一页纸**（`docs/PRODUCT.md`，给面试官的 3 分钟版） | 与 S1-1 同源；HR/面试官不会读 34 份 md | 我 |

**S1-1 的关键设计（防止新门面重复腐烂）**：产品页的数字**不手写**，
由 `scripts/build_product_page.py` 从 `docs/claims.json` 现算 + 渲染模板
（同 `real_data.html` 的既有做法）。于是：
- 页面与门禁**同源** → 不可能与 `claims.json` 打架；
- 模板入库、生成物入库（**这一处刻意破例**，见下 §五）。

## 二、"卡壳 → 大厂 API"：一个适配层，四个替换点

### 2.1 统一约束（**动码前必须满足，这一节是设计门**）

1. **一个适配层**：新增 `src/mm_curation/vendor/`，只暴露 OpenAI 兼容的
   `chat()` 与 `embed()` 两个函数。**凭据读环境变量，默认回落本机 Ollama**
   （本机已有 `qwen2.5:latest` / `llama3.1`）→ **离线即可验证流程，联网才换效果**，
   这样"调 API"不会变成"没有 key 就什么都跑不了"。
2. **不改协议**：不碰 `Sample` / `Operator` 签名（硬约束）；走既有 config 注入，
   **新需求新建 config，既有 4 个 config 一字不动**。
3. **对照实验是硬要求**：换 API 前后各跑一次，**同一冻结集、同一口径**，
   两边的数字都进 `claims.json`。
   ⚠️ **召回/误杀的分母必须仍是同一套注入 ground truth**（半合成注入，R11 那套）。
   分母换了 → 新旧数字**不可比** → **不许写进任何门面文档**。
4. **诚实边界（新增一条 PROOF_CHAIN 局限）**：外部 API 引入**不可复现性**（模型版本会漂移）。
   凡走 API 的数字，必须同时记 **模型名 + 调用日期 + 后处理参数**，并在 `PROOF_CHAIN`
   降级标注为「外部依赖，非位级可复现」。**这条不写清楚，整个"数字可复现"的招牌就自己砸了。**

### 2.2 四个替换点

| # | 替换点 | 现状（三审实点） | 换成什么 | 验收（可对外讲的数字） |
|---|---|---|---|---|
| **V-1** | **LLM-judge / 偏好判官** | δ 通用 0.5B 判官 **κ≈0**（诚实阴性）；ζ 域内 LoRA **κ=+0.560** | 大厂对话 API（接口本来就支持换 base_url） | δ 的 κ **由 ≈0 翻正**；η-b（抽取忠实性）同步重跑。**这是最漂亮的一条：阴性→阳性，且口径没动过** |
| **V-2** | **网页抽取层** | `trafilatura` 未装 → 走兜底器：救回率 100% / 丢失 0%，但**字数比 1.92×**、多抽段 88.9% | 大厂正文抽取/网页解析 API（或装上 `trafilatura` + LLM 二次筛选） | 60 篇同一对照集：**字数比 → ≤1.3×**，丢失率仍 0% |
| **V-3** | **语义去重嵌入** | 本地向量；10 万档 exact 1.0 / near **0.9714** / 21.1s | 大厂 embedding API（去重与检索两条链都重跑） | near 召回**不掉**、检索 R@1**不掉**。**掉一点就说明本地够用——那就如实报"不换"** |
| **V-4** | **工业轨时序异常检测** | 判据迁移后：C-MAPSS stuck 误杀 **30.58%→2.44%**；**SKAB 256 窗仍全零动作** | 大厂时序异常检测 API，**只作对照臂** | 三数据集上「自研算子 vs 云 API」**对照表**（不是替换） |

**V-4 的口径警告（写在最前，防止被误读）**：云 API 在这里是**对照臂，不是替换**。
把主轨换成黑盒 API 会**同时丢掉"逐条可归因"和项目最大的卖点**（判据迁移）。
所以 V-4 的产出是一张**对照表**——「成熟方案能做到多少 / 我们的差距在哪 / 差距为什么值得存在」。
**这张表比"我们调了个 API"更有面试价值**，因为它回答的是"为什么不用现成的"。

## 五、明确不做 / 明确降级（**收尾纪律**）

- **P1-1 服务层鉴权 → 降级为"文档化"**：发布形态选了零后端静态页，服务层只在本机跑。
  在 README/RUNBOOK 写明「**未鉴权，禁止公网暴露**」就够。**加了鉴权也没人用**，
  而且会给面试官"凑功能"的观感。
- **P1-2 流式/断点续跑**：按用户「都不砍」保留在 R2/R3，但**排在 V-1…V-4 之后**。
- **多租户 / 云原生 / 横向扩展**：不做（没有用户，这是"有用户之后"的问题）。
- **`docs/real_data.html` 的入库**：**不解除 gitignore**（2.42 MB 生成物，策略正确）。
  改为**新增一个轻量产品页**（`docs/product.html`，只内嵌 `claims.json` 的数字与结论，
  目标 <300 KB）→ 这是"生成物不入库"纪律下**唯一合理的破例**，且**只针对 ≤300 KB 的展示层**。
  > 破例判据（写下来防滥用）：**嵌入的是"注册过的数字"而不是"原始数据"**，体积可控，
  > 且它承担"外人第一眼"的职责。

## 六、S1–S3 的验收（每条都要"外人可验"）

1. **一条公网链接** → 打开就是产品结论 + 数字 + 诚实边界，不需要装任何环境。
2. **README 首屏** → 30 秒内能回答"这是什么 / 数字是多少 / 我怎么自己验一遍"。
3. **`python -X utf8 scripts/gap_audit_probe.py`** → 复审清单**可复跑**（本文件所依据的实点）。
4. **`mmc verify-claims`** → 新注册的结构性计数（S3-1）与产品页数字**都拦得住**。
5. **对照实验表**（V-1…V-4）→ 每个替换点都有"换前 / 换后 / 分母是什么 / 外部依赖标注"。

## 七、排序（避免"都想做"变成"都没做完"）

```
S1（看得见：产品页 → README → 一页纸）
  └─ 依赖：S3-1（先把门禁覆盖面补上，否则产品页重复 N-3 的错）
S2（闭环：人审队列 + 裁决页）        ← 与 S1 并行（glm 做队列，我做页）
S3（收尾小事）                        ← 随时可插入，都是半天内
V-1…V-4（卡壳换 API）                 ← 与上面并行，glm 为主；V-1 优先（阴性翻正最有价值）
R2/R3 原计划（滚动基线 / W4 配比层 / J1–J5）← 不砍，但**排在最后**
```

**一句话**：先把三审实点出的"看得见"这一栏做出来（S1+S2），
再把卡壳处换成成熟方案（V-1…V-4），收尾小事随手清（S3），
原计划的功能扩展不取消但排最后（R2/R3）。
