# 一条线：这个项目到底在解决什么

> **一句话**：把真实爬取的脏数据变成**带血缘、带质量证据、可被下游直接消费**的数据集——
> 中间每一道闸门都不是「我说了算」，它有一份注册表、一条红绿命令、一条失败归因。

> **本文档是主线的唯一出处。** 17 份`docs/*.md` 各有分工（见文末索引），
> 但「这项目解决什么问题」只有一个答案，就在这里。

> **面向岗位**：AI 数据开发 / AI 数据工程 / 数据平台开发。调研见 [JD_RESEARCH.md](JD_RESEARCH.md)。

## 一、问题：为什么「清洗干净了」这句话没有价值

任何人清洗数据都能说「我洗干净了」。这个说法无法被检验，所以没有价值。

真正能检验的说法只有一个：

> **把同样脏的数据交给两条不同的链路，哪条下游效果更好，差多少，为什么。**

这句话要能被追问到底，需要三样东西同时成立：

1. **脏数据有标注**——否则算不出检出率，只能自我感觉；
2. **口径可复现**——否则换个环境数字就变，结论无法复核；
3. **失败能归因**——否则只能看到一个总数字，不知道是哪个环节坏了。

这个项目做的事就是把这三样建起来，然后在上面跑真实实验。

## 二、链路：四道闸门，每道都有红绿证据

```
真实脏数据
   ↓
┌─────────────────┐
│ L1 规则算子│ ← 快、便宜，先跑
└─────────────────┘
   ↓
┌─────────────────┐
│ L2 感知模型       │ ← CLIP / 工业信号，需要编码
└─────────────────┘
   ↓
┌─────────────────┐
│ L3 LLM 判官       │ ← 最贵，只用于前两级拦不住的
└─────────────────┘
   ↓
带血缘 + 带质量证据的干净数据集
```

### 证据 1：清洗真的有效（不是检索指标好看）

**实验 A：灵魂实验**（`retrieval_eval.json`，1585 查询，全量重编码）

| 口径 | R@1 |
|---|---|
| 脏索引（`dirty_raw`） | 0.459 |
| 净索引（清洗后） | **0.556** |

净贡献 +21%。但**这一组不能排除「随便删点脏数据也能涨」**，
所以必须有实验 B。

**实验 B：零重编码对照**（`random_drop_baseline.json`，119 held_out，
同一索引不重编码，只换被删的那批样本）

| 对照 | R@1 | 说明 |
|---|---|---|
| 漏斗（按脏数据特征删） | 0.575 | 目标链路 |
| 随机丢弃（同数量，10 seeds） | 0.444 | 净贡献 **+0.131** |
| 只删干净样本（同数量） | 0.413 | **保留全部脏样本**，反向对照 |

**两个口径不许混**：实验 A 的 0.556 与实验 B 的 0.575 出自**不同实验**——
A 回答「清洗后检索好不好」，B 回答「增益是洗出来的还是删出来的」。
把 0.575 说成是 0.556 的对照，是本项目早期犯过的错（见 `ENGINEERING_NOTES.md`）。

第三行是这个设计里最关键的一格：**证明「删得准」比「删得多」重要**。
如果只做前两行，任何「多删一点」的方案都能自圆其说。

### 证据 2：脏数据真的伤模型（不是只在检索层好看）

| 场景 | 干净集训练 | 脏集训练 | 结论 |
|---|---|---|---|
| CLIP 微调 R@1 | 0.688 | 0.636 | 脏数据让模型变差 |
| 中文语料 GPT-2 困惑度 | 7.16 | 7.70 | 脏数据让模型更困惑 |

> ⚠️ **诚实边界**：CLIP 那组是**单 seed、无训练方差**。只能说「脏数据没有让它更好」，
> 不能说「脏数据一定让它更差」。见 [PROOF_CHAIN.md](PROOF_CHAIN.md) §九。

### 证据 3：门禁是有效的（不是「我说了算」）

医疗门禁（3 seeds 最差口径）：召回 **1.0** / 误杀 **0.0**（0/500）
工业门禁（3 seeds 最差口径）：召回 **1.0** / 误杀 **1.23%**（13/1056）

**用最差的那一seed 报**，不是平均值——门禁数据取最好看的那次就没有意义了。

### 证据 4：通用模型不认识你的域

| 判官 | 效果 |
|---|---|
| 通用判官 | κ **−0.024**（基本不相关） |
| 域专属 LoRA 判官 | κ **+0.560** |
| 偏好判官 | 0.532 → **0.839** |

结论：**在自己的数据上训练的判官，才配给自己的数据用。**

### 证据 5：算子知道自己要打什么靶

- `clip_alignment` 算子对主靶 `mismatched_pair` 的召回 **95.77%**
- 同一算子在干净集上的误杀 **0.19%**（4/2106）

一靶一命：说明算子是被设计过的，不是堆上去的。

## 三、协议抽象：换数据源不用重写

| 能力 | 证据 |
|---|---|
| 换模态/换域不重写 | 四模态接入同一协议，**零特例** |
| 双运行时一致 | local 与 Ray **逐 id 零差异** |
| 去重能力 | 10 万档 exact 召回 **1.0** |

「逐 id 零差异」这一条是协议抽象的硬检验：同一个输入在两个运行时必须给出**同一个答案**，
差一个 id 就说明有隐藏状态没被正确传递。

## 五、数据合成：为什么「增强」不等于「修脏」

前四节都是**清洗**。这一节是它的镜像方向：**造数据**。

| | 污染（`contamination/`） | 合成（`synthesis/`） |
|---|---|---|
| 干什么 | 往干净集里**加**脏 | 从真实样本**派生**增强样本 |
| 1→N 发生在 | `ContaminationPlan.run`（计划级） | `SynthesisPlan.run`（计划级） |
| ground truth | `labels.dirty` | `labels.synthesized_by` + `source_id` |

**为什么落在「计划级」而不是协议层**
协议层 `Transformer.transform(sample) -> TransformResult` 里
`TransformResult.sample` 是**单个** `Sample | None`，形状 1→1；
改成 1→N 会同时动包侧协议与所有既有算子的回归。
而污染器**早就是计划级 1→N**，所以合成沿用同一形状：
**不改协议就拿到了 1→N**，把「要不要改协议」留成独立议题。

### ★ 这条能力最重要的边界：**增强 ≠ 逆向还原**

读完 `contamination/impl.py` 的真实实现后可以确认，污染分两类：

- **可逆的**：叠字（`text[:8] + "哈"*30` 的叠字部分）、8-gram 重复、分句顺序
- **不可逆的**：`text[:3]` 截断、虚词整串替换、GBK 错解、换成广告图

声称能「修」不可逆的那些，就等于**编造内容**——
产出的不是「同一条样本的另一个形态」，而是凭空生成的新样本，
它的 ground truth 是假的。

这个边界不是事后补的说明，而是**开发中被自己的测试抓出来的**：
第一版写了个「`0→o` 噪声还原表」，而项目里的噪声注入用的是
`'的地得和与及或在是被有了一个'` 这类常用虚词整串替换——
**凭空设计一张「反向表」等于自己跟自己玩**，已删除。
完整可逆性对照表在 `src/mm_curation/synthesis/impl.py` 的模块 docstring 里。

### ★ 同口径可比：合成样本与真实脏数据放在同一张表里

「合成样本走了同一条漏斗」很容易做到。真正难回答的是**走了之后数字可比吗**。
所以是**三臂对照**——三臂过同一条漏斗、同一个阈值，真实语料（维基正文）：

| 臂 | 样本量 | 被拦 | 比率 | 拦它的算子 |
|---|---|---|---|---|
| A 真实干净 | 600 | 11 | **1.83%** | chinese_ratio 10 / line_repetition 1 |
| B 合成增强 | 394 | 5 | **1.27%** | chinese_ratio 5 |
| C 污染注入 | 300 | 131 | **43.67%** | char_repetition 47 / doc_length 46 / chinese_ratio 34 |

**判据是三条关系，不是三个数字**：

1. **合成臂 ≤ 背景 + 1pp** —— 增强**没有引入新误杀**。
   实测合成臂（1.27%）反而**低于**真实干净臂（1.83%）：
   压叠字、补句末标点、轮换分句这三种手段都在让文本更规整，
   而漏斗里 `chinese_ratio` 拦下的正是标点/符号占比异常的那类，
   所以增强臂被拦得更少是**方向上合理**的，不是巧合。
2. **注入检出 ≥ 背景 5 倍** —— 漏斗**看得见**要抓的东西。
   实测 43.67% / 1.83% ≈ **24 倍**。
3. **各臂 n ≥ 200** —— 否则比率不可信（实测 n=60 时干净臂比率在 11.7%，
   与 n=600 时的 1.83% 差 6 倍；这个阈值是实跑两档比出来的，不是拍的）。

三条同时成立才叫「同口径可比」。**只报其中一个都可能自圆其说**：
只报合成臂很低，可能是漏斗瞎了；只报注入检出很高，可能是漏斗过杀。

**⚠️ 三条口径不许混**（这一条是硬约束，不是提醒）：

- 1.83% 是**这批维基语料自带的异常比例上界**（确实混着广告模板、
  超短条目、段落复读——那些是真的该拦），**它不是「算子误杀率」**。
- 1.27% 也不是「增强引入的噪声」：合成样本来自同一个干净集，
  被拦的原因与A 臂**同源**。
- 只有 43.67% 才叫「检出率」。

门禁与变异测试：`scripts/synthesis_parity_gate.py`（3/3 变异拦红）。
变异基线必须与门禁**同一套参数**——第一版变异基线单写 n=300，
于是注入臂只有 150 条 → 基线红 → 纪律中止。
那不是判据的问题，是**「变异基线跑另一套参数」本身就是一种假绿**。

### 诚实边界

- 6 种增强手段、1→N 形状、溯源三元组、可复跑、**同口径可比**：已落地并有测试
- 只覆盖**纯文本 + L1 规则层**（6 个算子）。没加 `text_minhash`（batch 算子，
  分母与单样本臂不同口径）与 `perplexity`（需要 GPT-2 zh 权重，本机拉不到，
  门禁必须能离线跑）。这是**口径选择**，L1 已能分出三臂档位，加 L2 只改绝对值。
- **`Contaminator` 没有模态声明**（既有缺口）：图像类污染 kind 配到纯文本样本上
  会直接崩（`Sample.image_path` 是 None），而漏斗侧有模态门禁会拒。
  本节绕开它（只选文本类 kind），**没有假装它不存在**。

## 六、诚实边界（先说破，比被追问出来好）

这一节的存在比上面所有数字都重要。**没有边界的数字不值得信。**

### 能说的

- 脏数据检出率可算，且有随机丢弃对照排除「多删一点」的混淆
- 门禁用3 seeds 最差口径，不是最好那次
- 协议在四个模态上零特例接入，双运行时逐 id 一致

### 不能说的

| 不能说 | 原因 |
|---|---|
| 「CLIP 实验证明脏数据让模型更差」 | 单 seed 无方差，只能说「没让它更好」 |
| 「实现了缓慢变化维（SCD2）」 | `dim_device` 结构齐备但**设备属性从未变过**，拉链未经真实变化检验 |
| 「Agent 是生产级系统」 | 编排逻辑可复跑、可回归，但**不是**生产环境验证过的系统 |
| 「门禁保证数字为真」 | 门禁保证的是**一致性**，不是真值性 |

### 规模边界

- 工业传感器 3 个真实数据集，8 万行量级
- **跑不出数据倾斜/长尾分布**，规模相关的结论不成立

### 已登记的未完成项

以下数字**存在但未被门禁锁定**，用到时要自己先说破：

- CLIP 微调：**单 seed，无训练方差**（0.688 / 0.636 这组）
- 域专属判官 κ **0.560**、偏好判官 **0.839**、域外 κ **0.178**（域外差距大，需解释）
- MRR 0.599 → 0.670、near 0.9714（所需报告 JSON 不在库，**没有门禁**）
