# 面试叙事：多模态图文数据清洗与向量检索管道

> 本文档是面试弹药库：3 分钟电梯演讲、STAR 故事、预想追问与回答、简历 bullet。
> 所有数字均来自真实实验（见 data/reports/ + docs/ROADMAP.md 校准记录）。

## 一、3 分钟电梯演讲

> 我做了一个面向中文多模态大模型训练数据的端到端清洗管道。核心问题是：
> 真实爬取的图文对充满脏数据——重复、模糊、图文错配、低质文本——但**真实脏
> 数据没有 ground truth，无法量化清洗好坏**。
>
> 我的方法是用**程序化污染器**向干净种子集注入 10 类可控脏数据并保留标注，
> 这样每个清洗算子都能算 precision/recall。我搭了一条 11 级清洗漏斗（L1 规则
> → 去重四件套 → L2 Chinese-CLIP），再用 FAISS 建索引 + FastAPI 做检索服务。
>
> 灵魂实验是**清洗前后检索对比**：同一批查询，脏索引 Recall@1 = 0.459，
> 清洗后 0.556，**相对提升 21%**。我还发现"头部挤压"效应——污染主要挤的是
> top-1 名次而非 top-10。最后做了分层采样器：在干净集上按质量+类目配比采样，
> 比随机采样再提升 18~24%。Phase 2 把结论推到训练级：同一 CLIP 在脏集微调比
> 干净集低 5.2pp R@1——脏数据伤模型有了直接证据。94 个测试、四 tab Demo、
> Airflow DAG 一键复现。

## 二、STAR 故事

### Situation（背景）

中文多模态大模型训练面临数据质量危机：爬取的图文对含大量重复、模糊、错配、
低质文本。业界共识是"清洗规则驱动模型效果迭代"，但有两个痛点：
1. 真实脏数据没有 ground truth → 清洗效果无法量化
2. 清洗算子众多（去重四件套、质量检测、图文对齐），哪些真正有用？

### Task（任务）

用一套管道同时证明：清洗**有效**（下游检索提升）、清洗**可量化**（每算子 P/R）、
清洗**有依据**（阈值经真实数据校准）、清洗收益**可归因**（消融实验定位贡献最大的算子）。

### Action（行动）

**1. 程序化污染器（解决"无 ground truth"痛点）**
- 向 COCO-CN 干净种子集（1,620 对）注入 10 类脏数据（精确/近似重复、模糊、
  低分辨率、图文错配、低质文本、水印、NSFW 占位），共 486 条，每条带 `labels.dirty` 标注
- 污染强度经真实数据校准：pHash 裁剪从 >10% 收紧到 4~10%（避免与自然相似图混淆）

**2. 11 级清洗漏斗（YAML 配置驱动，算子可组合）**
- L1 规则层（文本长度/中文占比/字符重复 + 分辨率/长宽比/模糊度）→ 去重四件套
  （md5/pHash/MinHash-LSH/语义 embedding）→ L2 Chinese-CLIP（图文对齐 + 语义去重）
- 算力分级：CPU 规则算子在前缩小规模，GPU CLIP 最后跑（成本意识）
- 每个阈值都扫了"召回-误杀"曲线定位拐点（如 pHash t=12：召回 84%/误杀 0.3%）

**3. 算子级 P/R 独立评测（解决"哪些算子有用"痛点）**
- 关键洞察：漏斗串联会因上游拦截而低估下游召回（如 md5 会拦下只改 caption 的注入）
- 独立评测口径：每个算子在全量脏集上单独跑一次 → 完整召回矩阵
- 发现：blur 算子同时 100% 召回 low_resolution（污染器下采样→上采样成模糊图）

**4. 检索服务 + 灵魂对比实验**
- Chinese-CLIP 编码 + FAISS IndexFlatIP 双索引（clean=1585 / dirty=2106）
- FastAPI 服务（文搜图/图搜图），热查询 67ms
- 对比实验：**清洗使 R@1 0.459→0.556（+21%）、MRR 0.599→0.670**
- 发现"头部挤压"：R@1 退化 9.7pp vs R@10 仅 2.7pp → 污染挤的是头部名次

**5. 分层采样器（配比采样的下游收益）**
- 按 clip_alignment 质量分桶 × tags 类目交叉分层 + 高质量过采样
- 零重编码加速：复用全量索引过滤子集（IndexFlatIP 精确检索，子集排名不变）
- **分层在 3 个预算点全胜**：budget=1000 时 R@1 0.353→0.437（+24%）

**6. 消融实验（归因贡献）**
- 逐个移除算子：单个算子 ΔR@1 均为 0（非 load-bearing）
- 分组消融：去重组是唯一显著影响组（移除四件套 → R@1 -0.017，246 条重复回流）
- 结论：清洗是系统性工程，不是银弹算子

### Result（结果）

| 维度 | 指标 |
|---|---|
| 清洗收益 | R@1 +21%（0.459→0.556）、MRR +0.071 |
| 配比收益 | 分层采样 R@1 +18~24%（vs 随机） |
| 漏斗召回 | 脏数据召回 100%（486/486 零残留）、干净误杀 2.16% |
| 消融归因 | 去重组 ΔR@1 = -0.017（唯一显著组） |
| Phase2 训练证据 | CLIP 微调 clean vs dirty R@1 差 5.2pp |
| Phase2 检测器 | testB 泛化 87.3% / 主靶召回 100% / 误杀 0.8% |
| 工程 | 94 测试、Airflow DAG 7 阶段、Streamlit Demo 4 tab |
| 复现 | `make data && make funnel && make eval-*` 一键 |

## 三、预想追问与回答

### Q1：为什么选 Chinese-CLIP 而不是英文 CLIP？

英文 CLIP 的 tokenizer 词表缺中文 token，且视觉-语言对齐未在中文数据上训练——
对中文 caption 无效。Chinese-CLIP（OFA-Sys）在 5 个中文数据集 ~2 亿图文对上训练，
是中文图文对齐的官方开源基座。选型本身就是面试考点。

### Q2：你的 ground truth 是构造的，真实场景没有，怎么办？

这是核心 trade-off。构造 ground truth 是为了**量化验证管道设计**——证明每个算子
能抓到它的靶子、阈值在拐点上。真实部署时去掉污染器，漏斗本身不变；质量报告
（各级通过率 + 分数分布）仍然提供可观测性。我还发现构造的 ground truth 也有
局限：误杀的"干净"样本里有 COCO 自然存在的近重复（同场景连拍），真实业务中
这恰是该去重的——"ground truth 也有局限"本身就是好案例。

### Q3：单个算子消融都是 0，是不是说明算子没用？

不是。单个算子只丢 4~17 条样本，不足以撼动 top-1 排名。但**分组消融**显示去重组
移除后 R@1 -0.017（246 条重复回流）。这说明漏斗是 ensemble——每个算子贡献一小块，
整体清洗（移除全部 486 条脏数据）才驱动了 +21% 的灵魂收益。这也呼应了检索对比
实验的"头部挤压"：污染的量级决定影响深度。

### Q4：数据规模才 1.6k，能说明问题吗？

规模确实偏小，但项目的重点是**方法论可验证**而非规模。工程上我做了扩展路径
文档化：算子无状态 + 批量接口，单机跑通后可平移 Ray/Spark；FAISS IndexFlatIP
可换 IndexIVFFlat/HNSWFlat 支撑百万级。真实业务中，pipeline 逻辑不变，只是
数据源和算力升级。

### Q5：为什么不用 LLM-judge 做质量打分？

ROADMAP 预留了 L3 LLM-judge 接口（抽样打分、成本可控）。当前用 Chinese-CLIP
对齐分作为 L2 代理，已能覆盖错配检测（召回 96%）。LLM-judge 的定位是 L3 抽样
复核——对 L2 边界案例（对齐分在阈值附近）抽样送 LLM 打分，成本可控且更准。
这是成本分级设计的一部分。

### Q6：阈值是怎么定的？是拍脑袋吗？

不是。每个有阈值的算子都扫了 8 个点（phash 4~20、minhash 0.4~0.85、clip
0.2~0.5、semantic 0.85~0.99），画了"召回-误杀"曲线，选拐点。如 pHash t=12：
召回 84%/误杀 0.3%；t=14 突增到 2.09%——这就是"误杀悬崖"。配置写在 YAML 里，
换阈值 = 换配置文件，漏斗可重跑（昂贵算子分数复用）。

### Q7：分层采样为什么用 clip_alignment 做质量信号？

clip_alignment 是图文对齐余弦相似度，直接衡量"这张图和这段文字有多匹配"——
这正是训练数据的核心质量维度。相比单一指标（分辨率/文本长度），它捕捉的是
图文一致性的综合质量。tags 类目分层则保证长尾类目（如"乐器"vs"街道"）在采样后
仍有代表性。

### Q8：Airflow DAG 在容器里跑，CLIP 推理在宿主机 GPU，怎么协调？

算力分级设计：容器跑 LocalExecutor + CPU 可承受的规则算子，CLIP 批量推理在
宿主机 GPU venv（RTX 4060 8GB）。DAG 的 BashOperator 调宿主机脚本，数据通过
volume 挂载共享。这种分级是为了成本意识——GPU 只在需要时用，CPU 算子先缩小规模。

## 六、Phase 2：从代理指标到训练证据

> Week1-4 证明了「清洗提升检索质量（代理指标）」。Phase 2 把结论推到
> 「清洗提升模型训练效果（直接证据）」，并补上在线化与真模型两个产品化维度。
> 三张杀牌，按面试重要度排序：

### 杀牌 1 · CLIP 干净/脏集微调对比（P4，最强）

同一基座（Chinese-CLIP ViT-B/16）分别在干净集与脏集上等步数（100 步）微调，
再看检索指标——脏数据训出来的模型就是更差：

| 模型 | R@1 | R@5 | R@10 | MRR |
|---|---|---|---|---|
| base（不微调） | 0.556 | 0.824 | 0.901 | — |
| clean_ft（干净集微调） | **0.688** | 0.930 | 0.970 | 0.791 |
| dirty_ft（脏集微调） | 0.636 | 0.891 | 0.959 | 0.748 |

- 干净比脏高 **5.2pp R@1（相对 8%）**——「脏数据伤模型」第一次在训练效果层面被直接证明
- base 与 Week3 D3 基线互证一致（0.556），说明评测协议自洽
- 讲法：D3 是代理证据（检索质量），P4 是训练证据（模型效果）——闭环

### 杀牌 2 · 防循环论证的自训检测器（P1）

水印/NSFW 从占位实现升级为真模型（MobileNetV3-Small 三分类）。关键设计：
合成数据分风格组 A（训练+同风格 testA）和组 B（泛化测试），在**字体/透明度/
文本池/布局**四维刻意错开，B 组不参与任何训练决策——否则合成数据训出来的模型
只是在背自己的风格。

- testA 98.2% / **testB 泛化 87.3%**（水印召回 88%）
- 迭代教训：首轮无增广时 testB 水印召回仅 5.8% → 加颜色/裁剪增广逼模型学
  「文字叠加」不变特征 → 拉到 88%
- 阈值校准：默认 min=0.30（任一脏类 P>0.70 丢），误杀从 16.9% 降到 0.8%
- 主靶全量召回 100% / 干净误杀 0.8%

### 杀牌 3 · 在线质量门 + 增量去重（P2+P3，产品化）

批处理漏斗 → 实时数据链路：

- `POST /api/ingest`：base64 图 + caption 到达即评分 + 判重 + accept 判定
- 质量门与漏斗**共用一套算子/阈值配置**（从 PipelineConfig 构建）→ 在线判定
  与离线漏斗口径一致，这是对接真实数据管道（爬虫→质量门→入库）的前提
- 增量去重三层查-判-插一体：md5 / pHash 海明距离 / MinHash-LSH 原生增量
- 检测器权重缺失时自动降级（无 wm_nsfw 分数），不崩溃

### Phase 2 追问预案

- **Q：微调才 100 步，能说明问题吗？**
  100 步是受 8GB 显存与时间预算约束的取舍；结论方向（clean>dirty）在 50/100 步
  都稳定。真实场景会训到收敛，但「脏数据更差」的趋势已足够明显。
- **Q：检测器用合成数据训，真实水印不一样怎么办？**
  正是因此才做风格组 B 泛化测试——testB 87.3% 证明模型学到的是「叠加文字」概念
  而非记风格。真实部署可再加少量真实样本微调，框架不变。
- **Q：在线质量门和离线漏斗口径真的一致吗？**
  一致——两者都从同一 PipelineConfig 构建算子实例，阈值同源。差异只在单样本
  vs 批量接口（is_batch 过滤），批算子（如 wm_nsfw_cnn）在门里走 run_batch 单条。
