> 本文档是面试弹药库：3 分钟电梯演讲、STAR 故事、预想追问与回答、简历 bullet。
> 所有数字均来自真实实验（见 data/reports/ + docs/ROADMAP.md 校准记录）。
> 工程细节弹药库（59 条真实踩坑）见 docs/ENGINEERING_NOTES.md。

## 一、3 分钟电梯演讲

> 我做了一个面向中文多模态大模型训练数据的端到端清洗管道。核心问题是：
> 真实爬取的图文对充满脏数据——重复、模糊、图文错配、低质文本——但**真实脏
> 数据没有 ground truth，无法量化清洗好坏**。
>
> 我的方法是用**程序化污染器**向干净种子集注入 10 类可控脏数据并保留标注，
> 这样每个清洗算子都能算 precision/recall。我搭了一条 11 级清洗漏斗（L1 规则
> → 去重四件套 → L2 Chinese-CLIP），再用 FAISS 建索引 + FastAPI 做检索服务。
>
> 灵魂实验是**清洗前后检索对比**：同一批查询，脏索引 Recall@1 = 0.459，
> 清洗后 0.556，**相对提升 21%**。我还发现"头部挤压"效应——污染主要挤的是
> top-1 名次而非 top-10。最后做了分层采样器：在干净集上按质量+类目配比采样，
> 比随机采样再提升 18~24%。Phase 2 把结论推到训练级：同一 CLIP 在脏集微调比
> 干净集低 5.2pp R@1——脏数据伤模型有了直接证据。
>
> 但做到这里我发现：这些能力**不该只属于图文这一个模态**。所以 V2 把它重构成
> 框架——协议和算子 SDK 收口成可 pip 安装的包（`curation-eval`），管道退化成
> 框架的一个实例。我用 30.2 万篇中文维基语料做第二个实例来验证「模态可插拔」
> 不是口号：**零特例接入**，全量漏斗保留 60.3%，脏语料微调的 GPT-2 困惑度比
> 干净语料差 7.5%——图像侧「脏数据伤模型」的结论在文本模态上独立复现了。
> 执行层同样可替换：同一份 YAML 算子图改一行 `runtime: ray`，10 万档结果与
> 本地串行**逐 id 零差异**。
>
> 最后两步是让它能被长期依赖：L3 补上 LLM-judge，但我用 Cohen's κ 给它设了
> **准入门槛**——实测通用 0.5B 判官 κ≈0（判分与脏净零相关），判定不合格，我把
> 这个阴性结果原样写进了文档；再往后建了**数据 CI**，让「质量数字不达标」和
> 「代码测试挂了」一样会让流水线变红，而且我特地用劣化注入证明过它真的会红。
>
> 现在在做 V3：把 δ 暴露出的缺口（通用模型不认识你的数据域）做成一个平台——
> 用「自己的数据 → 自己的 benchmark → 自己的模型」三步，训一个域专属判官。
> 已达标：κ 从 0.013（通用）提到 **+0.560**（LoRA 微调，本机 8GB）；
> 训练层薄封装不自研，自研核心放在 benchmark 构建与数据工程闭环上。
> 双 CI（代码 + 数据）、157 + 40 个测试、四 tab Demo、Airflow 一键复现。

## 二、STAR 故事

### Situation（背景）

中文多模态大模型训练面临数据质量危机：爬取的图文对含大量重复、模糊、错配、
低质文本。业界共识是"清洗规则驱动模型效果迭代"，但有两个痛点：
1. 真实脏数据没有 ground truth → 清洗效果无法量化
2. 清洗算子众多（去重四件套、质量检测、图文对齐），哪些真正有用？

### Task（任务）

用一套管道同时证明：清洗**有效**（下游检索提升）、清洗**可量化**（每算子 P/R）、
清洗**有依据**（阈值经真实数据校准）、清洗收益**可归因**（消融实验定位贡献最大的算子）。

### Action（行动）

**1. 程序化污染器（解决"无 ground truth"痛点）**
- 向 COCO-CN 干净种子集（1,620 对）注入 10 类脏数据（精确/近似重复、模糊、
  低分辨率、图文错配、低质文本、水印、NSFW 占位），共 486 条，每条带 `labels.dirty` 标注
- 污染强度经真实数据校准：pHash 裁剪从 >10% 收紧到 4~10%（避免与自然相似图混淆）

**2. 11 级清洗漏斗（YAML 配置驱动，算子可组合）**
- L1 规则层（文本长度/中文占比/字符重复 + 分辨率/长宽比/模糊度）→ 去重四件套
  （md5/pHash/MinHash-LSH/语义 embedding）→ L2 Chinese-CLIP（图文对齐 + 语义去重）
- 算力分级：CPU 规则算子在前缩小规模，GPU CLIP 最后跑（成本意识）
- 每个阈值都扫了"召回-误杀"曲线定位拐点（如 pHash t=12：召回 84%/误杀 0.3%）

**3. 算子级 P/R 独立评测（解决"哪些算子有用"痛点）**
- 关键洞察：漏斗串联会因上游拦截而低估下游召回（如 md5 会拦下只改 caption 的注入）
- 独立评测口径：每个算子在全量脏集上单独跑一次 → 完整召回矩阵
- 发现：blur 算子同时 100% 召回 low_resolution（污染器下采样→上采样成模糊图）

**4. 检索服务 + 灵魂对比实验**
- Chinese-CLIP 编码 + FAISS IndexFlatIP 双索引（clean=1585 / dirty=2106）
- FastAPI 服务（文搜图/图搜图），热查询 67ms
- 对比实验：**清洗使 R@1 0.459→0.556（+21%）、MRR 0.599→0.670**
- 发现"头部挤压"：R@1 退化 9.7pp vs R@10 仅 2.7pp → 污染挤的是头部名次

**5. 分层采样器（配比采样的下游收益）**
- 按 clip_alignment 质量分桶 × tags 类目交叉分层 + 高质量过采样
- 零重编码加速：复用全量索引过滤子集（IndexFlatIP 精确检索，子集排名不变）
- **分层在 3 个预算点全胜**：budget=1000 时 R@1 0.353→0.437（+24%）

**6. 消融实验（归因贡献）**
- 逐个移除算子：单个算子 ΔR@1 均为 0（非 load-bearing）
- 分组消融：去重组是唯一显著影响组（移除四件套 → R@1 -0.017，246 条重复回流）
- 结论：清洗是系统性工程，不是银弹算子

### Result（结果）

## 三、预想追问与回答

### Q1：为什么选 Chinese-CLIP 而不是英文 CLIP？

英文 CLIP 的 tokenizer 词表缺中文 token，且视觉-语言对齐未在中文数据上训练——
对中文 caption 无效。Chinese-CLIP（OFA-Sys）在 5 个中文数据集 ~2 亿图文对上训练，
是中文图文对齐的官方开源基座。选型本身就是面试考点。

### Q2：你的 ground truth 是构造的，真实场景没有，怎么办？

这是核心 trade-off。构造 ground truth 是为了**量化验证管道设计**——证明每个算子
能抓到它的靶子、阈值在拐点上。真实部署时去掉污染器，漏斗本身不变；质量报告
（各级通过率 + 分数分布）仍然提供可观测性。我还发现构造的 ground truth 也有
局限：误杀的"干净"样本里有 COCO 自然存在的近重复（同场景连拍），真实业务中
这恰是该去重的——"ground truth 也有局限"本身就是好案例。

### Q3：单个算子消融都是 0，是不是说明算子没用？

不是。单个算子只丢 4~17 条样本，不足以撼动 top-1 排名。但**分组消融**显示去重组
移除后 R@1 -0.017（246 条重复回流）。这说明漏斗是 ensemble——每个算子贡献一小块，
整体清洗（移除全部 486 条脏数据）才驱动了 +21% 的灵魂收益。这也呼应了检索对比
实验的"头部挤压"：污染的量级决定影响深度。

### Q4：数据规模才 1.6k，能说明问题吗？

规模确实偏小，但项目的重点是**方法论可验证**而非规模。工程上我做了扩展路径
文档化：算子无状态 + 批量接口，单机跑通后可平移 Ray/Spark；FAISS IndexFlatIP
可换 IndexIVFFlat/HNSWFlat 支撑百万级。真实业务中，pipeline 逻辑不变，只是
数据源和算力升级。

### Q5：为什么不用 LLM-judge 做质量打分？

**δ 阶段我实装了，但验收是阴性——所以现在没让它上岗。** 这个答案比「我没做」
信息量大得多，建议主动讲：

- **实装**：L3 judge 做成普通注册算子（OpenAI 兼容协议、服务端可插拔），确定性
  抽样（sha1(seed+id)，重跑同批）、批内并发、失败语义 skip 优先（解析失败 →
  保留不评判，所以 judge 坏了漏斗不会死，只是掉覆盖率）。
- **验收**：用 Cohen's κ 对 ground truth 结算——**judge 不是真理，一致性才是
  可信度证明**。实测 Qwen2.5-0.5B 的 κ(t) 在 0.30→0.95 十个阈值点全平坦在 ±0.015，
  judge vs L1 κ=0.056；而同一个数据集上 L1 规则的 κ=0.565（对照组证明任务信号充足）。
- **结论**：判分与脏净零相关，**0.5B 没有判官资格**。不用它不是成本问题，是
  它现在不准——一个 κ≈0 的 judge 上线，等于请了个看起来能用的随机数生成器做质量
  裁决：它会静默放走脏数据、丢掉好数据，而且没有任何人会发现。
- **什么时候会用**：换 7B+ 或云端 API 只改 `base_url`，机制与验收协议一行不用动，
  κ 过线就上岗。更进一步，V3 已经把「域专属判官」做成了——用自己域的数据
  微调，κ 从 0.013 推到 **+0.560**，验收线 ≥0.5 达成（见第八节）。
- **成本分级设计仍在**：judge 只对 L1+去重+困惑度之后的 10% 抽样终审
  （`configs/text_funnel_llm.yaml`），是增强不是阻塞。

### Q6：阈值是怎么定的？是拍脑袋吗？

不是。每个有阈值的算子都扫了 8 个点（phash 4~20、minhash 0.4~0.85、clip
0.2~0.5、semantic 0.85~0.99），画了"召回-误杀"曲线，选拐点。如 pHash t=12：
召回 84%/误杀 0.3%；t=14 突增到 2.09%——这就是"误杀悬崖"。配置写在 YAML 里，
换阈值 = 换配置文件，漏斗可重跑（昂贵算子分数复用）。

### Q7：分层采样为什么用 clip_alignment 做质量信号？

clip_alignment 是图文对齐余弦相似度，直接衡量"这张图和这段文字有多匹配"——
这正是训练数据的核心质量维度。相比单一指标（分辨率/文本长度），它捕捉的是
图文一致性的综合质量。tags 类目分层则保证长尾类目（如"乐器"vs"街道"）在采样后
仍有代表性。

### Q8：Airflow DAG 在容器里跑，CLIP 推理在宿主机 GPU，怎么协调？

算力分级设计：容器跑 LocalExecutor + CPU 可承受的规则算子，CLIP 批量推理在
宿主机 GPU venv（RTX 4060 8GB）。DAG 的 BashOperator 调宿主机脚本，数据通过
volume 挂载共享。这种分级是为了成本意识——GPU 只在需要时用，CPU 算子先缩小规模。

## 六、Phase 2：从代理指标到训练证据

> Week1-4 证明了「清洗提升检索质量（代理指标）」。Phase 2 把结论推到
> 「清洗提升模型训练效果（直接证据）」，并补上在线化与真模型两个产品化维度。
> 三张杀牌，按面试重要度排序：

### 杀牌 1 · CLIP 干净/脏集微调对比（P4，最强）

同一基座（Chinese-CLIP ViT-B/16）分别在干净集与脏集上等步数（100 步）微调，
再看检索指标——脏数据训出来的模型就是更差：

| 模型 | R@1 | R@5 | R@10 | MRR |
|---|---|---|---|---|
| base（不微调） | 0.556 | 0.824 | 0.901 | — |
| clean_ft（干净集微调） | **0.688** | 0.930 | 0.970 | 0.791 |
| dirty_ft（脏集微调） | 0.636 | 0.891 | 0.959 | 0.748 |

- 干净比脏高 **5.2pp R@1（相对 8%）**——「脏数据伤模型」第一次在训练效果层面被直接证明
- base 与 Week3 D3 基线互证一致（0.556），说明评测协议自洽
- 讲法：D3 是代理证据（检索质量），P4 是训练证据（模型效果）——闭环

### 杀牌 2 · 防循环论证的自训检测器（P1）

水印/NSFW 从占位实现升级为真模型（MobileNetV3-Small 三分类）。关键设计：
合成数据分风格组 A（训练+同风格 testA）和组 B（泛化测试），在**字体/透明度/
文本池/布局**四维刻意错开，B 组不参与任何训练决策——否则合成数据训出来的模型
只是在背自己的风格。

- testA 98.2% / **testB 泛化 87.3%**（水印召回 88%）
- 迭代教训：首轮无增广时 testB 水印召回仅 5.8% → 加颜色/裁剪增广逼模型学
  「文字叠加」不变特征 → 拉到 88%
- 阈值校准：默认 min=0.30（任一脏类 P>0.70 丢），误杀从 16.9% 降到 0.8%
- 主靶全量召回 100% / 干净误杀 0.8%

### 杀牌 3 · 在线质量门 + 增量去重（P2+P3，产品化）

批处理漏斗 → 实时数据链路：

- `POST /api/ingest`：base64 图 + caption 到达即评分 + 判重 + accept 判定
- 质量门与漏斗**共用一套算子/阈值配置**（从 PipelineConfig 构建）→ 在线判定
  与离线漏斗口径一致，这是对接真实数据管道（爬虫→质量门→入库）的前提
- 增量去重三层查-判-插一体：md5 / pHash 海明距离 / MinHash-LSH 原生增量
- 检测器权重缺失时自动降级（无 wm_nsfw 分数），不崩溃

### Phase 2 追问预案

- **Q：微调才 100 步，能说明问题吗？**
  100 步是受 8GB 显存与时间预算约束的取舍；结论方向（clean>dirty）在 50/100 步
  都稳定。真实场景会训到收敛，但「脏数据更差」的趋势已足够明显。
- **Q：检测器用合成数据训，真实水印不一样怎么办？**
  正是因此才做风格组 B 泛化测试——testB 87.3% 证明模型学到的是「叠加文字」概念
  而非记风格。真实部署可再加少量真实样本微调，框架不变。
- **Q：在线质量门和离线漏斗口径真的一致吗？**
  一致——两者都从同一 PipelineConfig 构建算子实例，阈值同源。差异只在单样本
  vs 批量接口（is_batch 过滤），批算子（如 wm_nsfw_cnn）在门里走 run_batch 单条。

## 七、V2：从「一条管道」到「一个框架」

> 这是全项目**最有纵深**的部分。大多数候选人做的是「一个能跑的 pipeline」，
> V2 做的是「让第二个模态零成本接入的框架」——而且不是设计稿，是跑通的。
> 五张杀牌（α→ε）按面试重要度排序：
>
> **B（跨模态复现）> D（敢报阴性）> A（抽象能力）> E（工程成熟度）> C（可替换性）**
>
> 时间紧就只讲 **B + D**：一个证明你能抽象，一个证明你诚实。

### 为什么这个升级值钱（先讲动机，不要直接背功能）

- **V1 的痛点**：所有能力（污染器 / P/R 评测 / 漏斗 / 报告）都和「图文对」这个
  模态绑死。换到纯文本就得重写一遍——说明抽象层级不够，只是脚本集合。
- **我给自己定的判断标准**：能不能**零特例**接入第二个模态？能，才叫框架。
- 于是我用 30.2 万篇中文维基语料做了这个验证（β 阶段）。选纯文本是因为它与图像
  差异极大（离散符号 vs 连续信号），最能证明抽象与模态无关。

### 杀牌 A · 协议收口 + 反向吃狗粮（α）

把协议与算子 SDK 抽成独立 pip 包 `curation-eval`（四个抽象：`Sample` /
`modality` / 注册表元数据 / `Executor`），**主仓库反过来 `pip install -e` 消费它**。

- **吃狗粮是「可复用」最强的证明**：框架的创作者自己是第一个重度用户，
  不是「我造个包看看有没有人用」。
- 设计取舍：包只管「怎么定义算子、怎么执行、怎么评测」，**不碰任何具体模态**
  ——这是它能同时服务图文和纯文本的根本原因。
- 讲法要点：抽象不是提前设计出来的，是被第二个模态的真实需求逼出来的（见下）。

### 杀牌 B · 第二个模态零特例接入（β，最强）

| 维度 | 图像实例（V1/Phase2） | 文本实例（V2 β） | 协议是否改动 |
|---|---|---|---|
| 数据源 | COCO-CN 1,620 对 | 中文维基 **302,002** 篇 | 否 |
| 算子数 | 11 级 | 8 级（长度 / 中文占比 / 复读 / 模板句 / PII / 困惑度…） | 否 |
| 去重 | MinHash-LSH（datasketch） | 向量化 MinHash-LSH（80 perm / 8 band，numpy 自实现） | 否 |
| 训练证据 | CLIP 微调 R@1 差 **5.2pp** | GPT-2 zh 微调 ppl 差 **7.5%** | 否 |

- **零特例的含义**：没有为文本模态在协议层加任何一个 `if`。
- **跨模态复现是最硬的一条**：同一个「脏数据伤模型」结论，在两个模态、两个模型
  家族、两种指标（检索 R@1 / 语言模型困惑度）上**独立成立**——这说明它是数据质量
  的普遍规律，不是某个实验的偶然。这条比任何单个数字都值钱。
- 规模也跨了量级：1.6k → 30.2 万（**187 倍**），去重从小时级压到 60 秒
  （向量化签名，30 万档 60.4s 近线性）。

### 杀牌 C · 执行层可替换（γ）

同一份 YAML 算子图，`runtime: local` 与 `runtime: ray` 两种执行器，**算子零改动**。
10 万档双跑：kept 集相等 + 8 级 StageStat 相等 + **逐 id 分数零不一致**。

- **反直觉数字要自己先说**：20k 单样本算子在 Ray 上慢 35 倍，10 万档
  local 24.0s vs ray 89.6s——Ray 在这个规模**不划算**（对象列传输开销主导，
  且是 Windows 单机）。
- 但 γ 的目标从来不是性能，是**可替换性**：证明算子图与执行器解耦，换运行时
  不需要动任何算子。真上千万级多机才是 Ray 的战场。
- **主动暴露这个数字比藏起来更可信**——它同时证明你会用分布式、也清楚它的
  适用边界。这是区分「堆技术栈」和「懂工程取舍」的分水岭。
- 顺带一个真实收获：首跑不等价，归因发现「簇代表依赖块序」→ 批量算子改为
  按 id 规范化排序，从此跨运行时确定性（详见工程笔记 #53）。
- **γ3 之后补的图像模态验收**：文本漏斗验证过 ≠ 框架通用。图像漏斗（9 级 CPU
  算子，2106 条含注入污染）双跑，γ3 三口径 + 新增 dedup 标记口径（324 条
  duplicate_of 逐 id 相等）**四口径全等**——簇代表确定性在图像模态实测成立。
  附带发现：id 排序让字典序小的注入复制品当上簇代表，与污染集「种子在前」
  约定相反，duplicate_of 审计时要知晓（kept 质量不受影响）。

### 杀牌 D · LLM-judge 的准入门槛（δ，最敢讲的一张）

三层漏斗补齐最后一层 L3 judge：**做成普通注册算子**（不是特例分支），走 OpenAI
兼容协议、服务端可插拔。核心设计决策：**judge 不是真理，一致性才是可信度证明**
——可信度用 Cohen's κ 对 ground truth 结算，不合格就是不合格。

结论是**阴性的，而且我敢把它写进 README**：

| 口径 | 数字 | 含义 |
|---|---|---|
| 0.5B 判官 κ(t) | 0.30→0.95 十个工作点全平坦在 **±0.015** | 判分与脏净标签零相关 |
| judge vs L1 规则 κ | **0.056** | 判官与规则几乎不重合 |
| L1 规则 vs 标签 κ | **0.565** | 参照组：规则在这个任务上是有效的 |
| 机制健康度 | 解析成功率 69.5%、延迟 17.2s→10.7s | 链路全通，是判官不行不是管道不行 |

- **为什么阴性结果反而最值钱**：如果我不跑 κ 直接上线，这是个**看起来能用的随机数
  生成器**。κ 协议的全部价值，恰恰体现在它把这个 judge 筛掉了。
- **方法论闭环**：α 阶段证明了「阈值必须扫描」，δ 证明了「扫描只能救有信号的曲线，
  救不了平的」——两次实验合起来才构成完整的阈值方法论（笔记 #55）。
- **失败语义兜底**：解析失败 → 返回 None → 保留不评判。所以 judge 发疯时漏斗不会死，
  只是掉覆盖率（首跑 78% 解析失败时，数据一条没被误杀）。**先设计好「它坏了会怎样」**，
  调试时才不用祈祷。
- **成本意识**：换 7B 或云端 API 只改 `base_url`，机制与验收协议一行不用动。

### 杀牌 E · 数据 CI：给数据质量本身上锁（ε）

代码 CI 证明「逻辑对」，数据 CI 证明「数字达标」——**两层 CI 是工程成熟度的分水岭**。
大多数个人项目只有前者。

- 做法：6000 篇合成语料（seed 固定；用大词表随机组句，规避我在 β 吃过的「模板即重复」
  自相似坑）+ 300 条精确 / 700 条近似注入 → **真跑 `dedup_fast`** → 门限断言。
- 实测：exact 1.0 / near 0.954 / 误杀 0，**0.5s 跑完**（轻依赖，push/PR/每周定时都跑得起）。
- **关键的一步是证明门禁会红**：把阈值劣化到 0.95 再注入，实测 exit 1。
  一个从来没红过的门禁只是装饰品——这是我判断 CI 是否真实的唯一标准。
- **先标定生成器再定门限**：del=1+swap 使 J∈[0.86,0.92]（落在捕获带内），del=2 就跌破。
  门禁测的是实现，不是测生成器——如果生成器产出的损伤强度不可控，门限数字毫无意义。
  这条方法论直接来自 β 阶段「造测试数据被去重打脸三次」的教训（笔记 #49）。
- **同一方法论扩到图像（ε 补强）**：md5/phash 也被锁进门禁——2800 张合成图
  （含字节复制 + 裁剪重编码注入）真跑去重，exact 1.0 / near 0.994 / 误杀 0，
  劣化注入（裁剪加重）实测 near 跌到 0.152 → **exit 1**。标定中发现块状合成图
  对裁剪比真实照片敏感（裁剪移动块网格 → 低频错位），损伤三轮收窄到门限带内
  ——又是「先标定生成器再定门限」，第二次按它走就一次到位了。
- **第三层锁：阈值曲线回归门（ε2）**：单点门禁之上再锁「整条阈值敏感性曲线」——
  threshold_scan 曲线对冻结基线逐点比对（recall 偏移 >0.05 / 误杀 >0.02 即红）。
  防的是另一类漂移：**换库版本/换实现**（imagehash、datasketch 升级）时单测仍绿、
  单点门禁可能仍过，但曲线拐点先变。只锁轻依赖双主算子（minhash_lsh / phash_near），
  13s 跑完；基线里记录依赖版本，曲线变化可归因。

### V2 追问预案

- **Q：抽 SDK 包是不是过度设计？就你一个人用得着吗？**
  判断标准不是「有几个用户」，是「有没有第二个实例」。我已经用它跑通了图文和
  纯文本两个模态，抽象是被真实需求逼出来的；而且它是可 pip 安装的独立包，
  别人装就能用，不是内部目录划分。
- **Q：两个模态够证明「可插拔」吗？**
  严格说第三个（音频/视频）会更硬，但边际收益递减：图像与文本已是差异极大的
  两端，足以说明抽象与模态无关。我选择把精力放在 ε（数据 CI，让框架能被团队
  持续依赖）上——**证明「能长期维护」比再堆一个模态更能说明产品化**。
- **Q：文本去重为什么不用现成的 datasketch，要自己实现？**
  两个原因：① 30 万档逐文档签名是小时级，向量化后 60 秒；② 自实现才能改 LSH 的
  rows/bands——后面救场就靠这个。语料里有海量「模板化条目簇」（上千个只换人名的
  开国少将条目），它们把 LSH 桶撑爆，我用捕获公式 `1-(1-J^rows)^bands` 重新定了
  参数（rows 6→10、bands→8），near 召回从 0.42 拉回 0.97。
- **Q：β 阶段印象最深的一个 bug？**
  union-find 的合并方向。`parent[rx] = ry` 让**大索引一侧当簇代表**，而注入的
  重复样本永远在列表尾部——结果「重复副本被保留、真源文档被丢」，pair 明明合并了
  但召回算不出来。召回从 0.42 直接到 0.97。教训：**「先到先保留」这种约定如果不写
  成断言，就等于没有约定**（笔记 #46）。
- **Q：为什么你的工程笔记有 59 条？**
  因为真实踩坑才是最好的面试弹药。我每条都记「现象 → 根因 → 决策 → 数字 →
  话术」五段，其中最有价值的是那些**结果对但语义错**的隐蔽 bug（splitlines 撕碎
  JSONL、union-find 合并方向、污染器与算子各测各的却互相打不中）。
- **Q：δ 做出来是阴性，不算白做吗？为什么不直接上 7B 拿个漂亮数字？**
  两个原因：① 我的目标不是「让 L3 好看」，是**给 L3 建立准入门槛**——κ 协议
  存在的意义就是能说出「这个 judge 不合格」，如果只对能过的模型跑，协议就退化成
  橡皮图章；② 阴性结果指出了真问题（0.5B 不认识你的数据域），这直接成为下一阶段
  的立项依据（见第八节 V3）。顺带一提，我在本机 8GB 显存上确实跑不动 7B——
  但**受限条件下把机制做对、把结论说诚实**，比借算力刷一个数字更有说服力。
- **Q：κ=0.565 是规则做到的，那还要模型干什么？**
  这正是我给自己设的对照组的价值。它说明**任务本身信号充足**（不是不可学），
  所以「用模型逼近规则水平」是个合理目标；同时也提醒我——如果训出来的判官
  κ 只有 0.2，那不如直接留着规则，别为了用模型而用模型。规则和模型在漏斗里
  是分工关系（L1 拦结构损伤、L3 拦语义损伤），不是替代关系。
- **Q：数据 CI 和代码 CI 有什么本质区别？值得单独做吗？**
  代码 CI 防的是「改坏了逻辑」，数据 CI 防的是「换了一批数据，质量悄悄漂了」——
  后者才是数据管道的真实风险（上游换源、语料构成变化）。我做这两层是因为
  它们的失败模式完全不同：代码错了会 crash，数据烂了只会让下游模型**静默变差**，
  而没有任何人收到警报。

### V3 追问预案（立项阶段，被问到「下一步做什么」时用）

- **Q：V2 已经收官了，为什么还要做 V3？是在堆功能吗？**
  不是铺摊子，是 δ 的阴性结果**直接逼出来的**：κ≈0 说明「通用模型不认识你的
  数据域」，这是一个真实的、每个数据团队都会遇到的缺口。我是先有问题（δ 实测
  出来的），再立项解法，顺序和技术驱动的项目正好相反。
- **Q：微调这块 LLaMA-Factory / Unsloth 都做烂了，你再做一遍的价值在哪？**
  所以训练层我**薄封装不自研**——那是商品化的能力，重复造没意义。自研核心在
  另外两处：① **benchmark 构建**（通用 benchmark 评不了「我 care 的能力」，
  这一层几乎无人在做）；② **数据工程闭环**（用程序化污染造带标注训练对，
  这是我 α 阶段就验证过的方法论）。定位判断本身就是产品能力的一部分。
- **Q：κ 从 0.013 提到 0.5，凭什么觉得可能？**
  因为同一个数据集上 L1 规则的 κ=0.565——**任务信号充足，不是不可学**，
  0.5B 学规则级判别是合理目标。反之如果训出来只有 0.2，我就如实报告并
  保留规则方案：这正是 δ 教会我的——**数字不达标不等于没价值，藏着才算失败**。
  （后续：最终 κ=+0.560，与 L1 规则的 0.565 几乎打平——立项时的信号量
  判断被验证；但中间隔着两次阴性，能走到这一步靠的是根因链而非运气。）
- **Q：PRD 愿景是「按自己的偏好训练专属模型」，但你的判官学的是客观质量
  判别——这不是货不对板吗？**
  是差距，我把它**书面化了**而不是嘴上带过：PRD §九白纸黑字写了三条未兑现项
  （偏好未进闭环 / 任务域迁移零验证 / 产品化入口未做）。首战锚点解决的是
  「底盘真实可信」——四步骨架 + 防污染评测协议先立住，再谈偏好。η 阶段
  已按差距立项：**η-a 偏好闭环试点**（偏好操作化为详略维度，PA 精炼派 vs
  PB 求全派，persona-oracle 协议 + DPO，验收=两判官各自命中 ≥0.75 且
  分歧率 ≥40%）+ **η-c 域外泛化补账**。「先交付可验证的底盘、差距写进
  文档、下一阶段按差距立项」——这个顺序本身是产品判断力的一部分。

## 八、V3：从「一个框架」到「个人微调平台」（ζ 收官）

> 这一节讲的是**产品判断力**，不是又一个功能列表。面试时放在 V2 之后讲，
> 作用是回答那个必问题：「你接下来做什么 / 这个项目还能长到哪去」。
> **锚点任务已达标**：通用 0.5B 判官 κ=-0.024 → LoRA 微调 κ=+0.560（PRD
> 验收线 ≥0.5），且达标路上两次阴性训练的根因链本身就是最好的面试素材。

### 立项依据：V3 是被 δ 的阴性结果逼出来的

δ 的 κ≈0 不是一次失败，是一个**发现**：通用 Qwen2.5-0.5B 在中文网页语料上做质量
判官，判分与脏净零相关——**通用模型不认识你的数据域**。

这是个真实业务缺口：每个数据团队都有这一层，规则维护成本高、LLM 打分 API 按条收费。
于是 V3 的问题被定义得很具体：**能不能用自己域的数据，训一个专属小判官？**
（一次微调成本，换无限次廉价打分。）

注意这个顺序——**先有实测出来的问题，再有立项**，和技术驱动的项目正好相反。

### 产品定位：三步闭环

> 让个人研究者用「**自己的数据 → 自己的 benchmark → 自己的模型**」三步完成领域微调，
> 全程数字可验证。

**差异化判断（这段最能体现产品 sense，建议主动讲）**：

| 层 | 市面上 | 我的判断 |
|---|---|---|
| 训练 | LLaMA-Factory / Unsloth 已把微调做成商品 | **薄封装不自研**——重复造商品没意义 |
| 评测 | 通用 benchmark（C-Eval 等）评不了「我 care 的能力」 | **自研核心**：域 benchmark 的构建 |
| 数据 | 污染/标注方法论散落各处 | **自研核心**：程序化污染造训练对（α 已验证） |

定位本身就是能力：**知道哪一层不该自己造，比会造更难**。

### 锚点任务：专属数据判官（四步）

```
获取 → 清洗 → 造训练对 → 微调+评测
 │       │        │           │
 │       │        │           └─ LoRA(Qwen2.5-0.5B) → 冻结 benchmark 上结算 κ
 │       │        └─ 程序化污染 → 带质量标注的 (文本, 分数) 对
 │       └─ 复用 V2 漏斗（规则/去重/困惑度），零改造
 └─ 爬取新闻源，robots 合规 + 限速 + 幂等 → 统一 Sample 协议
```

**目标：κ 从通用的 ~0.013 提升到 ≥0.5，并如实报告域外泛化。**

**结果（2026-09-03）：κ=-0.024 → +0.560，达标。** P=0.706 / R=0.960 /
解析率 100%。达成路径比数字本身更有讲头——中间经历了两次阴性训练
（κ=-0.18 → -0.007 → +0.560），每一次阴性都定位到了具体根因（见下文
「三次训练的根因链」）。

### 三次训练的根因链（全项目最贵的一课，面试优先讲这段）

微调不是「跑通了」三个字能带过的——前两次训练 loss 曲线都「健康」，
κ 却都是阴性。真正的故事是这条根因链：

| 版本 | κ | 现象 | 根因 |
|---|---|---|---|
| v1 | -0.18 | loss 收敛正常，模板推理下输出干净 JSON | **协议错位**：裸 prompt 练、模板 prompt 考——instruct 模型的行为绑定在模板分布上，训练/推理根本不在同一个分布（笔记 #58） |
| v2 | -0.007 | 修正模板后 loss 依旧漂亮 | **completion 在窗外**：新闻正文 ~1500 token ≫ 窗口 432，右截断后判分 JSON 几乎永远落在窗口外——loss 上模型学的是「续写文章」，任务被**静默替换**（笔记 #59） |
| v3 | **+0.560** | prompt 按 completion 长度预留预算 + 训练/推理窗口统一 640 | 第一个 epoch loss 从 2.5 级跌到 0.69，最终 0.15；冻结 benchmark 一次过线 |

三个可讲的点：

- **loss 是模型在学「某个」任务的证明，不是在学「你要的」任务的证明。**
  任务被静默替换时，唯一症状在下游指标——这正是先造 benchmark 的价值：
  没有它，v2 的 bug 会永远藏在一条好看的 loss 曲线里。
- **打分直方图是实锤手段**：v2 的 clean 与 dirty 判分直方图双双变成
  「半数打 1 分」的双峰——判别信号根本没进损失。先看数据再改代码。
- **两次阴性各 40 分钟 GPU（本机 8GB）买来的认知**：协议位对齐和
  窗口预算是 SFT 的两条工程红线，已写进 RUNBOOK 作为微调 checklist。

**ζ2 的 benchmark 构建器值得单独讲**——它是 V3 自研核心，我给它设了三条硬约束：

- **版本冻结**：`benchmarks/judge_news_v1/items.jsonl` + `manifest.json`（含创建时间、
  标签分布、污染配比、seed），改一个字节都要升版本，否则训前训后对比无意义。
- **防污染**：benchmark 用 seed 9000、训练集用 seed 23，**两者隔离**；构建时强制跑
  md5 + MinHash 双重泄漏检查。这条直接来自 α 的方法论——评测集和训练集一旦
  有重叠，κ 就是自欺欺人。
- **准入指标**：构建过程本身要有数字（标签平衡、各类损伤实际条数），不是「随便捞
  300 条」就完事。

### 为什么 V2 的每一层都是 V3 的地基（叠加不重写）

这是我最想强调的一点——**V3 几乎没有从零写的东西**：

| V2 资产 | 在 V3 里的复用 |
|---|---|
| α 程序化污染器 + ground truth 协议 | 直接用来造训练对（带标注） |
| α/β 清洗漏斗 | 爬取数据的清洗，零改造 |
| δ 的 Cohen's κ 协议 | 判官验收的唯一判据 |
| δ 的 OpenAI 兼容 judge 接口 | 换 base_url 即可接微调后的判官 |
| ε 数据 CI | benchmark 与训练数据的质量门禁 |

**这不是堆功能，是复利**——前五个阶段每一层都在给下一层供弹药。面试时能讲出
这条复用链，比多报一个指标更能说明架构是设计出来的。
