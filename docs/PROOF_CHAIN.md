> 本项目的卖点是「清洗收益可证明」。卖点在哪，审计就打哪。本文档把证明链
> 摊开：每类质疑 → 仓库证据（实验/代码/报告）→ 已知边界。面向三类读者：
> 面试官（按 §八 十问索引）、协作 AI（按 §二-五 补实验）、未来的自己（§九 局限清单）。
> 生成日期：2026-09-18。所有数字可由 RUNBOOK 命令重新生成。

## 二、Ground truth 从哪来（质疑 1/13/17）

**机制**：真实脏数据没有标准答案，所以评测语料的脏样本全部由**污染器程序化注入**：
注入即复制（新 id、原始样本不动）、`labels.dirty = 污染类型`、注入类型与算子主靶
一一对应（每类脏数据有一个"负责它的算子"，测试锁定靶向命中）。语料与码表同源
（fhir_synth/sensor_synth 单一定义源），同 seed 逐字节可复现——标签可信性由
「干净语料在全部算子上零误杀」的语料级断言背书（笔记 #67）。

**单规则 P/R 怎么算（质疑 17）**：双口径设计——
- **独立口径**（`evaluate_all`）：每个算子在全量脏集上**单独跑一遍**，避免串联中
  上游拦截导致下游算子的召回被低估（operator_pr.md 固定脚注声明）；
- **串联口径**（`run_funnel` + 门禁）：端到端承诺，上游先拦灾难数据。

已知交互现象如实入账：全局统计算子（漂移/去重）的统计量会被其他注入污染，
独立口径下误杀偏高属预期（笔记 #68），端到端以串联门禁为准。

**多标签/比例（质疑 13）**：单标签（每条脏样本一个 dirty 类型）；注入率与各类
占比见报告 `manifest`（如 FHIR 500×0.3=150 条五类等权；工业 1056×0.3=317 条）。

## 三、收益是否因果（质疑 2/21-29，最致命 #2）

### 3.1 随机删同比例 baseline（本仓库最强的因果证据）

> 质疑：漏斗把 2106 条清到 1585 条，R@1 提升可能只是「删样本」。

实验 `scripts/eval_random_drop_baseline.py`：同一套零重编码评测口径
（dirty_raw 全量排名过滤子集，119 条 held_out 查询），随机删**同样 521 条**：

| 配置 | R@1 | R@10 |
|---|---|---|
| 漏斗子集（清洗规则删的 521 条） | **0.575** | 0.900 |
| 随机删 ×5 seeds | 均值 0.447（0.417~0.500） | — |

**清洗净贡献 = +0.128 R@1**。随机删不仅不提升还略降（删掉的 25% 里有干净样本），
漏斗的提升全部来自「删对了坏样本」。局限：5 seeds 不做正态置信区间（§九）。

### 3.2 灵魂实验口径（R@1 0.459→0.556）

`eval_retrieval.py`：同 1585 条查询集（held_out 119 / self 1466），脏索引 vs 净索引
对比——**0.556 是相对 0.459 的 +21%**（绝对 +9.7pp）；头部挤压效应已量化
（R@1 退化 9.7pp vs R@10 仅 2.7pp）。样本量小，±1pp 波动属正常，无多 seed 置信区间。

### 3.3 微调对比的控制变量（0.636 vs 0.688）

- CLIP（`finetune_clip.py` → `finetune_eval.json`）：同架构同超参同训练量，干净集
  0.688 vs 脏集 0.636 vs 不微调 0.556。**控制变量在报告字段**（steps/n_train）。
- GPT-2 文本（`finetune_gpt2.py` → `finetune_text_eval.json`）：报告字段
  `steps=1500, n_train=20000, dirty_rate=1.0`；ppl **绝对值 7.16 vs 7.70**
  （相对 +7.5%）——两个口径都给，防歧义。
- **测试集隔离（质疑 25/27）**：`_load_sets` 先切 2000 条干净 held-out 测试集
  再切训练集，代码级不相交；测试集与训练集同源维基的跨集近重复污染由
  去污染实验覆盖（跨集去重召回 94.4%，Phase2 P2）。
- **已知限制**：微调实验单 seed、无重复运行置信区间（GPU 成本）；「哪种脏类型
  最有害」的细粒度归因未做（batch 剂量实验只在数据 CI 的损伤强度标定中覆盖）。

## 四、门禁分层与可绕过性（质疑 30-36，最致命 #5/#8/#9）

### 4.1 CI 覆盖矩阵（什么真跑、什么离线）

| 层 | 内容 | 在 CI 里吗 |
|---|---|---|
| 代码测试 | 主仓 267 + 包 54（CLIP 用 FakeEncoder，纯 CPU） | ✅ ci.yml 每次 push |
| 数据质量门禁（轻） | 文本去重 0.5s / 图像去重 40s（真跑算子，劣化注入实测变红） | ✅ data-ci.yml |
| 阈值回归门 | MinHash/pHash 整条阈值曲线 vs 冻结基线，13s | ✅ data-ci.yml |
| 医疗/工业门禁 | eval-fhir / eval-industrial 各 ~6s | ⚠️ 本地/门户一键，未接 CI（接入是候选任务） |
| 训练级证据 | finetune_clip ~20min GPU、finetune_gpt2 | ❌ 离线，RUNBOOK 命令复现 |
| 规模基准 | 100 万档漏斗、Ray 双跑 | ❌ 离线，报告在 data/reports |

**简历数字的保证机制**：不由 CI 保证，由**可复现命令 + 报告落盘**保证——
数字→命令→报告的映射见 §七；CI 保证的是「规则逻辑不劣化」。

### 4.2 Goodhart 防护

- 门禁测的是合成语料上的算子行为，**阈值曲线回归门锁整条曲线**（逐点比对冻结
  基线，召回偏移 >0.05 / 误杀偏移 >0.02 即红），单点调参绕不过曲线；
- 劣化注入演练：文本/图像门禁都用「人为把算子调坏 → 门禁必须变红」验证过
  （exit 1 实测在案）；
- 门禁绿但业务方说下游降：**下游任务指标是终审**（分层裁决：算子 P/R → 漏斗
  门禁 → 下游证据），冲突时用归因报告（消融 ΔR@1）定位责任算子，而不是信门禁。

### 4.3 门限为什么是 90%/5%（最致命 #5）

**门限是回归红线，不是质量目标。** 实绩（医疗 100%/0%、工业 100%/1.04%）与
门限之间故意留出**劣化检测带**——若门限贴着实绩设 99%，任何微小波动都会让
CI 长期红，门禁就被人关掉了（Goodhart 的反面）。先例：文本去重实绩 near 0.954、
门限 0.90（留 4.5pp）；图像 near 0.994、门限 0.97（留 2.4pp）。合成语料难度
低于真实分布是已知边界（§五）——门限锁的是「不静默劣化」，不是「真实分布上
优秀」。

### 4.4 override（质疑 36）

`--no-gate` 观测模式存在且**留痕**（报告照常落盘、门禁结论照常写进报告）；
ops 侧失败仍渲染日报。个人项目无正式审批流，如实承认；设计上的审计钩子是
「绕过必有落盘记录」。

## 五、真实数据泛化（质疑 1/3/18/29，最致命 #1）

**已验证的真实轨**（双轨方法论：合成给 P/R，真实给曝光）：
- 维基 2066 篇真实爬取文本过漏斗：抓出 chinese_ratio 空白膨胀误杀 773 条
  （笔记 #65）→ 修算子语义 → 保留率 61.5%→98.3%，拦截数精确命中审计预测；
- 金融新闻每日运维飞轮（真实线上数据）：第一天 audit 抓到 46 条域误杀
  （阈值-域不匹配），进 backlog 校准——**域迁移出事的第一天就被抓到**，
  这正是门禁+审计飞轮的存在意义。

**纯合成的领域（如实标注）**：医疗 FHIR、工业传感器目前**只有合成语料验证**。
合成→真实的差距没有数字。验证计划：V5 β 接 NASA C-MAPSS 公开时序底座 +
注入实验；医疗需院内脱敏数据合作（在案未启动）。**在真实分布上，「还剩多少」
目前回答不了——这是本项目最诚实的边界。**

**对抗注入/未知脏类型（质疑 18）**：未覆盖，backlog。现有防线是规则白盒可审计
（每条被拦数据有 dropped_by 记录可抽样）+ 真实轨审计飞轮兜底。

## 六、竞品定位（质疑 2：为什么自研 curation-eval）

| 竞品 | 它做什么 | 它不做（本项目生态位） |
|---|---|---|
| Great Expectations / Deequ | 数据测试框架：断言由人手写 | 不提供清洗算子、无注入式 ground truth、无下游收益证明 |
| Cleanlab | 标签错误检测 | 不做清洗流水线与门禁闭环 |
| NeMo Curator / datatrove / dolma | 大模型语料清洗管道 | 有算子但评测薄：无注入式 P/R、无回归门、无下游任务证明链 |
| Data-Juicer | 算子最全的清洗生态 | 评测以统计启发为主；「算子好不好、收益多大」的回答仍缺（2026-09 对标调研结论） |
| LAION 过滤 | 一次性启发式过滤 | 无复用评测层 |

**一句话**：管道生态回答「怎么洗」，本项目回答「洗得对不对、收益多大、劣化了
谁知道」——与所有管道是叠加关系不是替代关系。

## 八、最致命十问 · 逐问索引

1. **合成自嗨？** → §五：图文/文本有真实轨证据；医疗/工业如实标注边界+计划。
2. **+21% 因果？** → §三：随机删 baseline 净贡献 +0.128；绝对 +9.7pp；样本量小如实说。
3. **0.636 vs 0.688 控制变量？** → §三：同超参同训练量（报告字段），细粒度归因未做。
4. **ppl 泄漏？** → §三：测试集代码级不相交 + 跨集去污染 94.4%；绝对/相对都给了。
5. **门限为什么低？** → §四三：回归红线留劣化检测带，不是质量目标；合成难度边界如实。
6. **误杀分母？换 seed？** → §七：0/500、11/1056；3 seeds 最差口径已入报告 `stability`。
7. **零改动改了什么？** → 准确说法是**框架层零改动**：协议/注册表/执行器/评测器
   0 diff（commit 26f4789、847baf2 文件清单可验证——sdk.py/registry.py/runner.py
   均不在变更列表）；领域增量 = 适配器+算子+污染器+语料+config+脚本六件套新文件，

9. **Goodhart / 门禁绿业务降？** → §四二/三：曲线回归门 + 下游指标终审 + 归因定位。

    只留一个功能：**污染器+门禁闭环**——没有它，其余一切数字不可信。

## 九、已承认的局限清单（不给辩护的）

1. 医疗/工业门禁数字全部来自合成语料，真实分布泛化未验证（计划在案未启动）。
2. 微调级实验单 seed，无置信区间；held_out 查询仅 119 条，±1pp 波动。
3. 对抗注入、未知脏类型、多语言、长尾/公平性：未覆盖。
4. 随机删 baseline 5 seeds，报区间不报置信区间（样本小，不装精确）。
5. 规模上 100 倍的答案停留在 100 万档实测（local 全区间胜，Ray 回本在多机），
   100TB 是推演不是实测。
6. GPU 推理非位级确定：等价性口径是集合/分数级一致（固定模型与精度），非逐位。
7. override 无审批流，只有落盘留痕（个人项目的真实形态）。
8. 「如果只能打标签不能删数据」：架构支持（score 留痕 + 阈值放行 = 人工审核
   队列模式），但没有实现审核队列产品。
