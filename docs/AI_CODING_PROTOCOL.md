# AI Coding 协议（本项目适配版）

> 适配自通用"文档驱动 + 分层生码"范式，领域词汇按数据管道项目替换。
> 原则不变：设计先行 → 任务拆解 → 分层实施 → 自测归档。

## 硬性规则

### 1. 文档驱动
任何功能写码前，先更新 `/docs/design_tables.md`，必含三表：
1. **数据结构表**：字段、类型、序列化格式、消费方（替代"业务实体表"）
2. **接口约定表**：FastAPI 的 URL/Method/出入参/校验；CLI 的参数/输入输出文件/退出码
   （替代"应用服务表"；无 API 的模块只写 CLI 约定）
3. **流转表**：样本生命周期 / 索引构建状态 / DAG 任务依赖（替代"状态机流转表"）

再生成 `/docs/tasks.md`：按本模块声明的纵向层次拆原子任务（50-150 行/任务）。

### 2. 分层生码
- 一个任务只写一层，禁止一次输出多层
- 每个模块的层序在 tasks.md 开头声明（不同模块层序不同，不套用固定模板）
- 层间确认门：**任务 = 代码 + pytest 证据 + 状态报告**，用户确认后才进下一任务

### 3. 上下文继承
进入新任务时显式引用已确认的前置产物（文件路径 + 设计表条目）。

### 4. 禁止一次性完成
指令含"全部搞定/一次性写完"时，拒绝并回到 tasks.md 逐任务执行。
例外：单文件 bug 修复 <20 行可跳过流程，但需简述修改点。

### 5. 自测与归档
- 每任务附 pytest 结果；模块完成生成 `docs/test_cases.md`（curl/命令行示例 + 预期输出）
- 模块验收后归档到 `docs_archive/<模块名>/`

## 输出格式（每个编码回复）
1. 【状态报告】当前阶段（设计/拆解/第 N 任务实施/自测归档）
2. 【产出物】具体文件路径 + 测试证据
3. 【下一动作】用户需要做什么
