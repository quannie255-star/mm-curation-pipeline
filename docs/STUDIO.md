# 多模态数据清洗 Studio（给非技术用户）

> 面向产品经理 / 业务人员 / 个人使用者：**上传你自己的数据 → 得到可直接训练的
> 数据集**，全程在浏览器里点，不碰命令行、不碰 YAML、不碰代码。
>
> 底层就是本仓库的多模态清洗漏斗（30 个算子、4 档代价），
> 这里只是给它套了一层人话界面。**没有任何清洗逻辑是另写的一套。**

---

## 1. 三步启动

```bash
python scripts/run_studio.py
```

浏览器会自动打开 <http://127.0.0.1:8765>。

| 情况 | 怎么办 |
|---|---|
| 端口被占用 | 报错会告诉你换成哪个：`python scripts/run_studio.py --port 8790` |
| 不想自动开浏览器 | 加 `--no-browser` |
| 想让别人访问 | 加 `--host 0.0.0.0`（⚠️ 会暴露到你的内网，见 §6） |

**前提**：本机有 Python 和项目依赖（`pip install -e .`）。不需要 GPU 也能用 ——
只有图文场景的 `clip_alignment` 算子会慢，页面会明确告知。

## 2. 四步向导

### 第1 步 选场景

四个场景卡，每张卡写清了三件事：**你的数据长什么样**、**会检查什么**、**产出什么**。

| 场景 | 适合谁 | 必填字段 |
|---|---|---|
| 图文语料（图片 + 配文） | 爬来的图文对、素材库 | `image_path` + `text` |
| 纯文本语料（文章/新闻/文档） | 语料清洗、知识库入库前处理 | `text` |
| 医疗合规（FHIR JSON） | 医院/保险理赔数据 | `text`（内含 FHIR 资源） |
| 工业时序（传感器读数） | IoT、设备日志 | `text`（内含时间+读数） |

**卡上每张都有中文标签**，告诉你这一步在干什么：

- 🟢 **规则**：纯字符串/数值判断，微秒级，不花钱
- 🔵 **感知**：图像/音频级别的判断，需要一点计算
- 🟡 **模型**：要跑神经网络（可能需要 GPU）
- 🟣 **大模型**：要调LLM API（**会产生费用**）

代价档越高越慢越贵，所以卡片会写明"需 GPU""会产生 API 费用"。

> ⚠️ 每个场景都有 **caveats**（已知的会误伤/需要注意的点），直接显示在卡片上，
> 不藏着。比如"中文字符占比检查会把英文语料当成脏数据扔掉"。

### 第 2 步 上传数据

支持 `.jsonl` / `.json` / `.csv` / `.tsv` / `.txt`，图片单独传 `.zip`。

- **不需要有 `id` 字段** —— 会按行号自动补（这是实测踩过的坑：
  `id` 是内部协议的必填项，用户数据通常没有，不补的话症状是
  "界面显示 96 条，文件里其实有 120 条"且完全看不出原因）。
- 上传后**先做体检再放行**：字段够不够、有没有坏行、多少条、
  哪些字段用不上（只是提示，不拦）。
- **所有文件只在你自己的电脑上处理**，不联网、不上传任何服务器
  （页面顶部有明示，测试里也有一条 `test_不用外部CDN` 盯着这件事）。

### 第 3 步 跑清洗

点"开始清洗"，页面会实时显示进度。跑完给出**逐级统计表**：

| 算子 | 进 | 出 | 丢了 | 通过率 |
|---|---|---|---|---|
| 太短或太长的没信息量片段 | 120 | 115 | 5 | 95.8% |
| 近似重复（转载、改写、同稿多发） | 115 | 113 | 2 | 98.3% |
| … | | | | |

**为什么要有这张表**：清洗是**有损**的，用户必须能逐条归因"我的数据为什么少了"。
只给一个"清洗完成，剩 113 条"是不负责任的。

#### 真实跑出来的一屏（12 条测试语料，纯文本场景）

| 检查项 | 进 | 出 | 丢弃 | 通过率 |
|---|---|---|---|---|
| 太短或太长的没信息量片段 | 12 | 11 | 1 | 91.7% |
| 中文字符占比（防止混入乱码或其他语种） | 11 | 11 | 0 | 100.0% |
| 字符多样性（单字/单句复读机） | 11 | 11 | 0 | 100.0% |
| 行级重复（同一行反复出现） | 11 | 11 | 0 | 100.0% |
| 模板套话（「综上所述」这类填充句） | 11 | 11 | 0 | 100.0% |
| 个人隐私信息（姓名/手机/身份证/邮箱） | 11 | 11 | 0 | 100.0% |
| **近似重复（转载、改写、同稿多发）** | 11 | 9 | **2** | 81.8% |
| 语言模型困惑度（机械感强的文本） | 9 | 9 | 0 | 100.0% |

语料里埋了 2 条转载（与前面的新闻完全相同）+ 1 条只有1 个字的。
结果：**转载被精确识别 2 条、太短被拦 1 条，其余一条没误伤**。

⚠️ 注意「整段复读」那条**没被抓住**（复读文本的字符重复得分 0.998，
阈值 0.8 分不开它）—— 这就是下面 §4 诚实限制里写的那条。

### 第 4 步 拿数据集

点"生成训练数据集"，产出：

```
data/studio/datasets/<名字>/
├── train/ val/ test/     # 已切分，test 是留出不训练的
├── manifest.json         # 血缘：来源、多少样本/词元/块、泄漏检查结果
└── recipe.json
```

`manifest.json` 是**唯一真相源** —— 下游训练脚本读它，不读你的记忆。

## 3. 数据格式要求

以纯文本场景为例：

```jsonl
{"text": "今日北京市发布新一轮优化营商环境措施……", "id": "n1"}
{"text": "国务院常务会议决定进一步优化营商环境……"}
```

- 每行一个 JSON 对象（`.jsonl`）或 CSV 的一行
- 唯一真正必需的是场景卡上写的 `必填字段`
- `id` 可选（自动补）
- 其余字段会**保留但不参与清洗判定** —— 页面会列出哪些字段用不上

**UTF-8 编码**（不是 GBK）。CSV 支持 Excel 导出的 UTF-8 BOM。

## 4. 已知限制（如实说明）

| 限制 | 实测数据 | 怎么补|
|---|---|---|
| **整段复读可能漏检** | 复读文本字符重复得分 0.998 vs 正常0.974，阈值 0.8 分不开 | 跨文档重复由 `text_minhash` 抓；单份内的整段复制目前**漏检** |
| MinHash 阈值区有误判 | 0.55–0.95 区间误判率约 7%（num_perm=320） | 加签名位数可降；不能靠调阈值（会损失真重复召回） |
| 单机运行 | — | 分布式路线尚未跑通（见 `docs/ARCHITECTURE_FOR_REVIEW.md`） |
| 无鉴权 | — | 只监听 `127.0.0.1`。别用 `--host 0.0.0.0` 暴露到公网 |

## 5. 底层是什么

Studio **不重写清洗逻辑**，它是一层薄壳：

| 层 | 位置 | 作用 |
|---|---|---|
| 场景配方 | `src/mm_curation/studio/recipes.py` | 「业务场景 → 算子组合 + 阈值」的映射 |
| 上传体检 | `src/mm_curation/studio/checkers.py` | 文件能不能跑、缺什么字段 |
| 后端 | `src/mm_curation/studio/backend.py` | 任务调度、漏斗调用、结果汇总 |
| HTTP | `src/mm_curation/studio/serve.py` | 标准库 `http.server`，零新依赖 |
| 前端 | `src/mm_curation/studio/static/` | 原生 HTML/CSS/JS，无构建步骤 |
| **真漏斗** | `src/mm_curation/pipeline/` | 逐级算子 + 阈值判定 |
| **真数据集构建** | `src/mm_curation/dataset/` | packing / 切分 / 泄漏检查 |

**配方的阈值不是拍脑袋定的**，逐条对齐 `configs/` 下真实跑通的配置
（如 `configs/news_zh_funnel.yaml`、`configs/funnel_fhir.yaml`）。

配方与算子注册表的一致性由 `recipes.assert_recipes_valid()` 强制，
**导入模块时自动跑**，不一致直接抛异常：

- 引用了未注册的算子
- 算子不支持本场景的模态（实测抓到过：`unit_consistency` 只支持工业模态，
  被误用进 FHIR 配方）
- 场景没声明算子需要的字段
- **算子缺中文说明**（双向检查：配方用到但没说明、说明过时）

## 6. 安全边界

- 默认只监听 `127.0.0.1`，**别人访问不到**
- 会话 id 做过路径穿越防护（有测试）
- 上传文件大小有上限，文件类型白名单
- **没有鉴权、没有多用户隔离** —— 它是"本地单人工具"，
  不是"多人 SaaS"。要多人用请自己在前面加一层认证网关。
- 上传的数据会留在 `data/studio/`（已 gitignore）。删会话就删目录。

## 7. 开发者：加一个新场景

1. 在 `recipes.py` 的 `RECIPES` 里加一个 `Recipe`：
   写清`title` / `blurb`（给人话）、`required_fields`、`operators`（算子+阈值）、
   `produces`、`sample_hint`、`caveats`（已知会误伤的点）
2. 在 `OPERATOR_ZH` 里给每个用到的算子加中文说明
3. 跑 `python -c "from mm_curation.studio.recipes import assert_recipes_valid"`
   —— 不一致会响亮失败
4. 前端**零改动**：场景卡是数据驱动的

测试会覆盖：配方↔注册表一致、中文说明双向同步、上传体检的每条拒绝规则、
前端 DOM 契约（JS 引用的元素必须存在、步骤与面板必须对齐）、
以及完整端到端（真起 HTTP 服务 → 真上传 → 真跑漏斗 → 真拿数据集）。
