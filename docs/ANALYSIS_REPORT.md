# 清洗策略对下游检索质量的影响：一份分析报告

> 面向读者：业务方 / 面试官 / 非技术决策者。
> 与 `REAL_DATA_REPORT.md` 的分工：那篇是**工程评测报告**（判据在真实数据上灵不灵），
> 这篇是**分析报告**（清洗这件事值不值得做、值多少、哪里不确定）。
>
> 全文数字均来自 `docs/claims.json` 锁定的落盘报告，**口径已在 §1.1 表内钉死**——
> 两组 R@1 数字看着接近但不可互换，混用会得出错误结论。

---

## 0. 结论先行

| # | 结论 | 证据强度 |
|---|---|---|
| 1 | 清洗后下游检索 R@1 从 **0.459 提升到 0.556**（+21.0% 相对，+0.097 绝对） | 强（1585 查询，同查询集同索引结构对照） |
| 2 | 这 +21% **不是「少了一半数据所以好找」**：同样删 521 条的随机对照组只到 0.444，漏斗比它高 **+0.131** | 强（10 seeds，95% CI 上界 0.464 仍低于 0.575） |
| 3 | 收益主要来自**删对了对象**，不是删够了数量：只删干净样本、把脏数据全留下的对照组反而降到 0.413 | 强（同一对照设计下的第三个臂） |
| 4 | 清洗后的语料微调，下游 R@1 0.688 vs 脏语料 0.636（+8.2%）；困惑度 7.16 vs 7.70 | 中（**单 seed，无训练方差**，只能当方向性证据） |
| 5 | 固定预算下按质量分层采样再拿 **+24%**（budget=1000） | 中（预算极紧时存在反例，见 §5.2） |

**建议**：清洗值得做，但**按当前口径只能承诺「低误杀 + 逐条可归因」，不能承诺「清洗效果好」**
（真实数据上没有数据质量真值，见 §5.1）。优先投入方向是补齐真值，而不是继续调阈值。

## 1. 业务问题与指标口径

### 1.1 问题

图文检索库里混进了低质量样本（乱码、复读、模板页、图文不匹配）。
清洗会**同时**带来两个效应：删掉噪声（正面）和减少库容量（负面）。
所以「清洗后 R@1 涨了」本身**不能**证明清洗有效——库变小本来就好找。

这正是本报告要回答的核心：**涨的这部分，有多少是「删对了」，有多少只是「删了」。**

### 1.2 指标选择

| 指标 | 选择理由 |
|---|---|
| **R@1（Recall@1）** | 主指标。检索场景用户只看第一个结果，top-10 命中但排第 8 等于没命中 |
| R@5 / R@10 | 辅助。用于检查收益是不是只发生在头部 |
| MRR | 辅助。对排名位置敏感，验证 R@1 的收益不是排名抖动 |
| **随机删对照的 margin** | **核心因果指标**。漏斗 R@1 − 随机删 R@1 均值 = 清洗规则的净贡献 |

### 1.3 ⚠️ 两组 R@1 不可互换（口径表）

| 口径 | 来源 | 查询集 | R@1 | 用途 |
|---|---|---|---|---|
| **灵魂实验** | `retrieval_eval.json` | 1585 条全量查询 | 脏 0.4593 / 净 **0.5558** | 对外讲的「+21%」 |
| **随机删对照** | `random_drop_baseline.json` | 2106 样本、删 521、target 子集 119 | 漏斗 **0.575** / 随机 0.4442 | 证明「删对了」的因果对照 |

两个 0.55 与 0.575 **来自不同查询集与不同运行**，相差约 0.02。
把它们当成同一个数去算差值，会凭空多出一个不存在的收益。**本报告全程分开引用。**

## 2. 对照设计（为什么这样能回答因果问题）

单臂实验（清洗前后对比）无法分离「删对了」和「删了」。设计了三个臂：

| 臂 | 处理 | 删除量 | 回答的问题 |
|---|---|---|---|
| **A · 漏斗** | 按清洗规则删 | 521 | 清洗的真实效果 |
| **B · 随机删** | 随机删同样多条 | 521（10 seeds） | 「只删了」能拿多少 |
| **C · 只删干净** | 随机删干净样本，**486 条脏数据全保留** | 同量 | 脏数据是不是真的有害 |

- **A − B > 0** → 收益超出「删了」的部分，即清洗规则的**净贡献**。
- **A − C** → 脏数据残留造成的**代价**，是对「脏有害」这一前提的直接检验。
- B 用 **10 个随机种子**而不是 1 个：单个种子下随机删的 R@1 在 0.417~0.500 之间波动，
  只看一个种子很容易把运气当成结论。

## 3. 结果

### 3.1 主结果：清洗有效（+21%）

| | 脏索引 | 净索引 | 绝对变化 | 相对变化 |
|---|---|---|---|---|
| **R@1** | 0.4593 | **0.5558** | +0.0965 | **+21.0%** |
| R@5 | 0.7912 | 0.8240 | +0.0328 | +4.1% |
| R@10 | 0.8744 | 0.9009 | +0.0265 | +3.0% |
| MRR | 0.5989 | 0.6699 | +0.0710 | +11.9% |

1585 条查询，同一个查询集、同一套索引结构，唯一变量是「库有没有清洗」。

**这张表本身就验证了 R@1 选得对**：收益高度集中在第 1 位（+21.0%），
到 top-10 只剩下 +3.0%。也就是说清洗主要改善的是「把正确结果顶到第 1 位」，
而不是「把正确结果弄进候选集」——若当初选 R@10 作主指标，
这个实验会被判成「几乎没效果」。

### 3.2 核心结果：收益来自「删对了」，不是「删了」

| 臂 | R@1 | 离散程度 | 与漏斗之差 |
|---|---|---|---|
| A 漏斗 | **0.575** | — | — |
| B 随机删 | 0.4442 | σ=0.0317，95% CI [0.4245, 0.4638]，10 seeds 范围 0.4167~0.500 | **+0.1308** |
| C 只删干净（脏全留） | 0.4133 | σ=0.0243，95% CI [0.3983, 0.4284] | **+0.1617** |

读法：

- 随机删 10 个种子里**最好的一个**（0.500）仍然低于漏斗（0.575）——
  不只是均值领先，是分布完全不重叠。
- 只删干净样本、把 486 条脏数据全留下的那一臂，**比随机删还差**（0.4133 < 0.4442）。
  这一条同时说明两件事：脏数据确实有害，且有害程度大于「少了几百条好数据」的损失。

**结论**：+21% 里至少 +13 个百分点是清洗规则的净贡献，不是样本量减少的副产品。

### 3.3 下游迁移：清洗后的语料微调也更好

| | 干净语料 | 脏语料 |
|---|---|---|
| 微调后 R@1 | **0.6883** | 0.6360 |
| GPT-2 困惑度 | **7.16** | 7.70（高 7.5%） |

⚠️ **单 seed，无训练方差**，这组数字只能当方向性证据，不能报置信区间。

### 3.4 配比：固定预算下的采样策略

budget=1000 时，分层采样 R@1 **0.353 → 0.437（+24%）**。
这里的效果与清洗**正交**：清洗决定「库里有什么」，采样决定「用哪些」。

## 4. 稳健性

- **随机删用了 10 seeds**，报告了 σ 与 95% CI，不是单次抽样。
- **设置了「只删干净」反臂**，用来证伪「脏无害」这一前提——它确实被证伪了。
- **阴性结果留档**：微调实验首跑困惑度只差 0.4%（噪声级），
  拆成剂量 / 损伤类型 / 长度混杂三层归因后重造损伤集，才得到现在的 7.5%。
  首跑数字作为灵敏度下界保留：**10% 轻度污染在该规模下不可测**。
- **分层采样有反例**：budget=800 时分层 R@10（0.445）反而略低于随机（0.454）——
  预算极紧时高质量层配额挤占了类目覆盖。这个反例被记录而不是被删掉。

---

## 5. 局限（这部分决定了这些数字能怎么用）

### 5.1 真实数据上没有「数据质量真值」——最硬的一条

三个真实数据集（C-MAPSS / MetroPT-3 / SKAB）的标签
（`degraded`、`fault_window_air_leak`、`sensor_anomaly`）**全是过程故障**，
没有一个是数据质量真值。因此：

- 真实轨的召回数字**不是能力指标**，对外只能讲「低误杀 + 逐条可归因」；
- 本报告的 +21% 建立在**半合成注入评测**上（靶子由我们自己造），
  **不是**在真实脏数据上测出来的；
- 可对外讲的注入召回：C-MAPSS 76.6%→85.2%、MetroPT-3 81.2%→89.9%、SKAB 87.8%→93.2%。

### 5.2 其它

| 局限 | 影响 |
|---|---|
| 微调实验单 seed | 无训练方差，不能报 CI |
| 去重组 ΔR@1 −0.017 未落盘 | 分组结果没有产物，引用时必须标注为**历史数字** |
| 稳态假设已被证伪（R7 如实未做） | 时序判据的改进数字是在错误假设下测的，正解是滚动基线 |
| 分层采样反例（budget=800） | 采样策略非单调占优，不能无条件推广 |

---

## 6. 建议

1. **继续做清洗，但改口径**：对外从「清洗效果好」改成「低误杀 + 逐条可归因」，
   与 §5.1 的证据强度匹配。
2. **下一步投真值而不是投阈值**：真实轨的主要瓶颈是没有数据质量标签。
   做 200~500 条人工标注，比继续调包络参数的边际收益高一个量级。
3. **把本报告的三个对照臂固化成 CI**：任何清洗规则改动都必须重跑 A/B/C，
   尤其守住 **A − B ≥ 0.05** 这条线（claims.json 已在校验它）。
4. **采样策略按预算档位给建议**，不要给单一结论：budget ≥ 1000 用分层，
   budget ≤ 800 时明确告知 R@10 可能受损。

## 附：数据质量现状（由 `mmc` 生成，非手工维护）

```bash
python -X utf8 scripts/mmc.py build && python -X utf8 scripts/mmc.py scorecard
python -X utf8 scripts/mmc.py metrics --verify && python -X utf8 scripts/mmc.py contracts
```

当前实点（4 个数据集 × 5 个质量维度 = 20 个格子）：

- 覆盖率加权健康度 **0.980**，平均覆盖率 **0.371**，破线 0
- **健康度必须和覆盖率一起引用**：0.37 的覆盖率意味着只有约三分之一的规则真正跑过，
  剩下的是 `NOT_EVALUATED` 而不是「通过」
- 唯一性维度因算子「只丢不打留分数」而记为 `OBSERVED`（有动作、无通过率语义），
  不用 0 分惩罚它正常工作
- 时效性维度全部 `NOT_EVALUATED`——当前数据集没有采集时刻语义，
  **宁可留空也不拿文本长度去凑一个时效性指标**
- 4 份数据契约共 52 条断言全部通过，其中含跨层对账（DWS 汇总 vs DWD 明细）
