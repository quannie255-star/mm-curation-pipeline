三、数据岗最该讲的三张牌

第 1 张 · 程序化污染器：把「清洗好不好」变成可计算问题

问题：真实爬取的脏数据没有标签，算不出 precision / recall，清洗只能是玄学。

做法：向干净种子集（COCO-CN 1,620 对）注入 10 类可控脏数据（精确/近似重复、模糊、低分辨率、图文错配、低质文本、水印、NSFW 占位…）共 486 条，每条带 labels.dirty 标注。

关键细节：污染强度必须与算子阈值联合校准。pHash 的裁剪强度从 >10% 收紧到 4~10%——剪太狠会和自然相似照片不可区分，校准就失真了。

产出：脏数据召回 99.8%（485/486），干净误杀 2.16%；每个算子都有独立 P/R（phash_near 84% / 0.24%，clip_alignment 96% / 0.19%）。

第 2 张 · 阈值不是拍脑袋：联合校准 + 敏感性扫描

每个有阈值的算子都扫 8 个点，画「召回-误杀」曲线，选拐点而不是选最好看的点：

算子阈值召回误杀结论
phash_near1065%0太紧
phash_near12（默认）84%0.3%拐点
phash_near1490%2.7%误杀悬崖
minhash_lsh0.65（默认）94%0.7%拐点

到 ε 阶段更进一步：把整条阈值曲线冻结进基线做回归门禁（recall 偏移 >0.05 或误杀 >0.02 即红）——防的是换库版本（imagehash / datasketch 升级）时单测仍绿、但曲线拐点先漂的那类静默退化。

第 3 张 · 数据 CI：给数据质量本身上锁

代码 CI 证明「逻辑对」，数据 CI 证明「数字达标」。两者失败模式完全不同：代码错了会 crash，数据烂了只会让下游模型静默变差，而没有人收到警报。

  • 合成带标注语料真跑去重：exact 1.0 / near 0.954 / 误杀 0，0.5s 跑完（轻依赖，push/PR/每周定时都跑得起）
  • 图像侧同款门禁：exact 1.0 / near 0.994 / 误杀 0
  • 关键一步是证明门禁会红：注入劣化后实测 exit 1（near 跌到 0.152）。一个从来没红过的门禁只是装饰品
  • 方法论：先标定生成器再定门限——损伤强度不可控，门限数字就毫无意义

V3 是被 V2 的阴性结果逼出来的（顺序很重要）

V2 阶段实装了 L3 LLM-judge，但用 Cohen's κ 一测：通用 Qwen2.5-0.5B 判官的 κ 在 0.30~0.95 十个阈值点全平坦在 ±0.015——判分与脏净零相关，而同一数据上 L1 规则的 κ=0.565。结论：通用模型不认识你的数据域。这不是失败，是一个发现，它直接定义了 V3 要解决的问题。

六、诚实边界：三处阴性结果原样公开

这是本项目区别于「刷数字型作品集」的地方——所有数字都来自真实实验，不达标的照写：

① δ：0.5B 判官不合格

κ(t) 全阈值域 ≈0，judge vs L1 仅 0.056。判定不合格，未上线。κ 协议的全部价值，恰恰体现在它把这个 judge 筛掉了——否则它就是个看起来能用的随机数生成器。

② η-b：抽取忠实性判官首轮未达标

0.53 / 0.50 / 0.41 ≈ 通用基线。归因：阅读对齐超出 0.5B 能力下限。转化为「判官能力矩阵」产品概念（哪个能力需要多大的模型），而不是粉饰成达标。

③ η-c：域外泛化衰减如实报

域内 κ 0.560 → 域外 0.178（召回跨域保持 0.969，精确率腰斩到 0.546）。结论写成「换域需重训、骨架可复用」。

八、高频追问预案

Q：你的 ground truth 是构造的，真实场景没有，怎么办？
构造是为了量化验证管道设计——证明每个算子能抓到靶子、阈值在拐点上。真实部署去掉污染器，漏斗本身不变，质量报告（各级通过率 + 分数分布）仍提供可观测性。而且构造的 ground truth 也有局限：误杀的「干净」样本里有 COCO 自然存在的近重复（同场景连拍），真实业务中这恰是该去重的——「ground truth 也有局限」本身就是好案例。
Q：单个算子消融 Δ 都是 0，是不是说明算子没用？
单个算子只丢 4~17 条样本，撼动不了 top-1。但分组消融显示去重组移除后 R@1 −0.017（246 条重复回流）。漏斗是 ensemble，整体清洗才驱动 +21% 的灵魂收益。
Q：数据规模才 1.6k，能说明问题吗？
规模确实偏小，但重点是方法论可验证。工程上扩展路径已文档化：算子无状态 + 批量接口可平移 Ray/Spark；FAISS 可换 IVF/HNSW 支撑百万级。而且 β 阶段已经把规模推到 30.2 万篇（187×），去重从小时级压到 60s。
Q：数据 CI 和代码 CI 有什么本质区别，值得单独做吗？
代码 CI 防「改坏了逻辑」，数据 CI 防「换了一批数据，质量悄悄漂了」——后者才是数据管道的真实风险。失败模式完全不同：代码错了会 crash，数据烂了只会让下游模型静默变差。
Q：Ray 实测比本地还慢，这不白做了吗？
20k 单样本算子在 Ray 上慢 35 倍，10 万档 local 24.0s vs ray 89.6s——这个数字我主动写进文档。γ 的目标从来不是性能，是可替换性：证明算子图与执行器解耦，换运行时不动任何算子。暴露边界比藏起来更可信。
