# 路线图：一条线

> **一条线：把脏数据变成可信训练数据，每一道闸门都能被第三方复跑。**
>
> 输入是真实爬取/开源的脏数据，输出是带血缘、带质量证据、可被下游直接消费的数据集。
> 中间每一道闸门都不是「我说了算」——它有一份注册表、一条红绿命令、一条失败归因。

**面向岗位**：AI 数据开发 / AI 数据工程 / 数据平台开发。见 [JD_RESEARCH.md](JD_RESEARCH.md)。

---

## 一、为什么收敛成一条线

2026-09 之前这个项目有 V1–V7 七条并行的版本线（协议收口、双运行时、LLM 判官、
偏好闭环、四模态扩展、领域包、平台轨），对外叙事被拆成了七段。
七条线的问题不是工作量，而是**没有一个非工程岗能在一分钟内判断「这项目到底解决了什么」**。

收敛的判据只有一条：**这一步有没有让「脏数据 → 可信数据集」这条链路上某个原本靠人判断的环节，
变成可复跑的门禁。** 没有的，一律降为实现细节或直接砍掉。

---

## 二、这条线现在到哪了

四个能力，全部已落地且有红绿证据：

| 能力 | 做什么 | 硬证据 |
|---|---|---|
| **质量闸门** | 算子化清洗漏斗，L1 规则 → L2 感知模型 → L3 LLM 判官，脏数据检出可算 P:R | Recall@1 **0.459 → 0.556**（+21%）；随机丢弃基线只 +0.131 |
| **协议抽象** | 换模态/换域不重写，算子无状态、local/Ray 逐 id 零差异 | 四模态接入同一协议零特例；Ray 与 local 逐 id 一致 |
| **数据系统** | 从脚本升级为有运行概念的数据系统：湖分区、DuckDB 契约闸门、台账 | 分区裁剪字节级证据 2736 B / 1885232 B → 少扫 **99.85%** |
| **域判官** | 自己的数据训练自己的判官，而非信任通用模型打分 | 通用判官 κ −0.024 → 域专属 LoRA **+0.560**；偏好判官 0.532 → 0.839 |

规模基线（**唯一真相源 = `docs/claims.json`**，改一处全文档红）：主仓 **623** + 包 **67** = **690** 条测试。
工程发现 **ENGINEERING_NOTES.md（96 条）**，每条是「现象 → 根因 → 决策 → 话术」。

## 三、下一步（按顺序，只做这三件）

**1. 把七条版本线的对外叙事压成一条**
代码分层不动，文档只留一条主线。历史细节不删——留在 `ENGINEERING_NOTES.md` 按编号可查。
验收：README 首屏 30 秒内能让非工程岗说出「这项目解决什么问题」。

**2. 补唯一还缺的那一格：数据合成与增强**
10 个在招岗位里 5 个要求 Data Synthesis / Augmentation，而本项目只有**反向**的污染器
（往里加脏）。协议层的 `Transformer` 目前只能 1→1（unchanged / replaced / unusable），
合成是 1→N——**通道形状不对，这是协议变更，不是加个算子**。
红线：合成样本必须走同一条漏斗，否则「我合成了一批数据」不可证伪。
验收：新通道 1→N 生效，且合成样本的检出率与真实脏数据同口径可比。

**3. 把门禁从「文档一致」推到「结论可信」**
现在的门禁能保证 690 条测试、96 条笔记、所有对外数字互相一致——
**它保证的是一致性，不是真值性**。下一步是把 `verify_claims.py` 接进 CI（当前只在本地跑），
并给覆盖率棘轮再加一层：已被注册但半年没被复核的 claim 主动标黄。
验收：一次 CI 运行同时验「数字没漂」和「门禁本身仍能拦红」（变异测试进 CI）。

## 四、明确不追

写下来比装看不见强：**PB/EB 级实跑**、**Agent 行为数据与 RLHF 全链路**、**论文级产出**、
**音视频新模态**、**PE/Agent 应用开发**。原因不是做不动，是它们与「一条线」正交——
补进去只会让项目重新变成七条线。
