# 路线图：一条线

> **一条线：把脏数据变成可信训练数据，每一道闸门都能被第三方复跑。**
>
> 输入是真实爬取/开源的脏数据，输出是带血缘、带质量证据、可被下游直接消费的数据集。
> 中间每一道闸门都不是「我说了算」——它有一份注册表、一条红绿命令、一条失败归因。

**面向岗位**：AI 数据开发 / AI 数据工程 / 数据平台开发。见 [JD_RESEARCH.md](JD_RESEARCH.md)。

---

## 一、为什么收敛成一条线

2026-09 之前这个项目有 V1–V7 七条并行的版本线（协议收口、双运行时、LLM 判官、
偏好闭环、四模态扩展、领域包、平台轨），对外叙事被拆成了七段。
七条线的问题不是工作量，而是**没有一个非工程岗能在一分钟内判断「这项目到底解决了什么」**。

收敛的判据只有一条：**这一步有没有让「脏数据 → 可信数据集」这条链路上某个原本靠人判断的环节，
变成可复跑的门禁。** 没有的，一律降为实现细节或直接砍掉。

## 二、这条线现在到哪了

五个能力，前四个已落地且有红绿证据，第五个在建：

| 能力 | 做什么 | 硬证据 |
|---|---|---|
| **质量闸门** | 算子化清洗漏斗，L1 规则 → L2 感知模型 → L3 LLM 判官，脏数据检出可算 P:R | Recall@1 **0.459 → 0.556**（+21%）；随机丢弃基线只 +0.131 |
| **协议抽象** | 换模态/换域不重写，算子无状态、local/Ray 逐 id 零差异 | 四模态接入同一协议零特例；Ray 与 local 逐 id 一致 |
| **数据系统** | 从脚本升级为有运行概念的数据系统：湖分区、DuckDB 契约闸门、台账、数仓建模（dbt） | 分区裁剪字节级证据 2736 B / 1885232 B → 少扫 **99.85%** |
| **域判官** | 自己的数据训练自己的判官，而非信任通用模型打分 | 通用判官 κ −0.024 → 域专属 LoRA **+0.560**；偏好判官 0.532 → 0.839 |
| **智能编排**（在建） | 用 Agent 做漏斗的**自适应路由**与**记忆压缩**，只省成本不许掉质量 | 目标：LLM 判官调用量下降、R@1 与静态基线持平、决策逐条可复现 |

> 第五个能力的定位见 [NARRATIVE.md](NARRATIVE.md)；它的**红线**是
> 「Agent 只能省成本，不能掉质量」——R@1 与静态基线不持平就是回归，不接受。

规模基线（**唯一真相源 = `docs/claims.json`**，改一处全文档红）：主仓 **876** + 包 **67** = **943** 条测试。
工程发现 **ENGINEERING_NOTES.md（99 条）**，每条是「现象 → 根因 → 决策 → 话术」。

主线叙事的唯一出处是 [NARRATIVE.md](NARRATIVE.md)；本文件只管边界与进度。

**1.5. image_caption 九形态召回补齐** ✅ 已完成（2026-10-08）
新增 `configs/pipeline.v3_full_coverage.yaml`（**既有 4 个 config 一字不动**），
补上B 步证伪实验查出的四个缺口：watermark（漏配 `wm_nsfw_cnn`）、
paragraph_repeat（`char_repetition` 量的是单字符游程，与段落级重复**语义不匹配**，
改用 `line_repetition`）、boilerplate_inject / pii_inject（对应算子原为
`text_article` 单模态，在 image_caption 上接了也不评）。
实现手法：给三个算子单独声明 `_TEXT_AND_CAPTION` 多模态，**不动模块级共享的
`_TEXT` 常量**（否则连带改变 doc_length/perplexity/text_minhash 的既有行为）。
三个新阈值取**实测分离度间隙中点**（干净组恒1.0，污染组 max 0.33/0.80/0.66），
不是拍脑袋：boilerplate 0.90 / pii_detect 0.83 / line_repetition 0.67。

| 形态 | 原配置 | v3 配置 |
|---|---|---|
| boilerplate_inject | 1/30 (3.3%) | **30/30 (100%)** |
| paragraph_repeat | 3/30 (10.0%) | **30/30 (100%)** |
| pii_inject | 2/30 (6.7%) | **30/30 (100%)** |
| watermark | 0/30 (0%) | **28/30 (93.3%)** |
| **合计** | **144/270 = 53.3%** | **256/270 = 94.8%** |

**代价必须同时报**：干净集（600 条原始样本）丢弃 1.33% → **2.50%**，
其中`wm_nsfw_cnn` 净增 1.17%（7 条，与 docstring 声称的 1.0% 同量级）。
三个新算子在干净集上**零误杀**（分项里查无它们）。
⚠️ 94.8% 是**合成污染注入**下的数字，与真实轨口径不同、不许混。

**2. 补唯一还缺的那一格：数据合成与增强** ✅ 框架已落地，同口径检出率待测
落点选择：**计划级合成器**（`src/mm_curation/synthesis/`，仿照 `ContaminationPlan`，
一条真实样本 → N 条增强样本），**未改协议层**——理由是污染器那边已经是计划级 1→N，
先对齐能少动包侧接口。已注册 6 种增强手段（3 文本 + 3 图像）。
红线遵守情况：合成样本带 `synthesized_by` / `source_id` / `clean` 三元组溯源，
运行时断言**绝不带 dirty 标记**，且「什么都没改」的样本会被丢弃
（否则合成量虚增一倍而报表看不出来）。
⚠️ **未完成**：合成样本的检出率与真实脏数据**同口径可比**这一条还没测——
需要把合成集喂进既有漏斗跑一遍。这是本项剩下的工作。
**踩过的坑已写进代码注释**：`text_deredup` 原先声称能「复原」污染注入的文本，
实测不能（`text[:8] + "哈"*30` 的前 8 字之后已丢失）——
**增强 ≠ 逆向还原**，这条边界写进了 `impl.py` 的可逆性对照表。

**3. Agent 编排与记忆压缩**（当前在建）
技术选型用业界成熟方案：**LangGraph**（状态图编排）+ 项目自有的策略层。
分层：`agent/graph.py` 编排、`agent/policy.py` 决策（**纯函数、零 LLM**）、
`agent/memory.py` 记忆压缩、`agent/budget.py` 成本记账。
