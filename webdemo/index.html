03 / 自己验一遍

三条命令，不用 GPU、不用下载数据

要验上面的数字是不是真的，跑这三步就够——如果跑不通，说明我写错了，那比数字错更严重。 

# 1. 装（Python 3.11）
pip install -e packages/curation-eval --no-deps

# 2. 跑核心实验（合成轨，数分钟）
python -X utf8 -m mm_curation.cli run

# 3. 跑真实数据集 + 晋升到 prod
python -X utf8 -m mm_curation.cli run  # 真实数据路径
python -X utf8 -m mm_curation.cli promote

每条命令的实测输出、venv 踩坑、报错排查 → RUNBOOK。 数字为什么可信（逐个追溯到报告与指针） → PROOF_CHAIN。

05 / 诚实边界

这个项目没做到什么

这一节比上面所有数字加起来更重要。一个只报优点的演示，它的数字就不该被当真。

真实数据的召回不是能力指标 真实轨的「脏」是过程故障（缺字段、格式漂移），不是人为注入的对抗样本， 所以真实轨召回高不代表判据好——只说明低误杀且逐条可归因。
background_flag_rate 不是误杀率 它是数据自带异常率的上界。三种口径不能混着讲。
0.575 是零重编码对照，不是主结论 主结论是 0.459 → 0.556（+21%）。两个数常被混起来引用。
门禁解决一致性，不解决真值性 verify_claims.py 有 67 条门面 + 变异测试，但它只能保证「文档和报告一致」， 保证不了「报告里的实验没跑错」。后者只能靠复现。
这一页的数字每次跑批都会变 看板那部分是快照，第 2 节的结论数字是登记在 claims.json 的稳定值。 两者刻意分开：稳定的锁进注册表，漂移的走独立通道并在页面上标注。
